# 阶段2.5：游戏化数据准备 - 详细可执行方案

## 一、目标与范围

### 目标
为阶段3（游戏设计功能）准备足够的数据基础，使游戏设计功能不只是原型，而是有实际参考价值的工具。

### 范围
- 扩充游戏案例至12个（覆盖更多玩法类型）
- 完善现有6个游戏案例的游戏设计字段
- 为10个经典非游戏案例添加"游戏化改编建议"
- 建立诡计类型→游戏机制映射表
- 建立3-5个基础游戏模板

### 不在范围
- 不修改前端 UI（阶段3再做）
- 不扩充非游戏案例数量（已有44个足够）
- 不做完整的游戏引擎集成

#### 1.1 案例选择（覆盖玩法类型）

| 序号 | 案例名称 | 玩法类型 | 选择理由 |

| 5 | 传送门2 | 推理解谜 | 空间推理，机制驱动的关卡设计 |

#### 1.2 数据字段（每个案例需填写）

```
基本信息：案件名称、来源类型=["游戏"]、来源作品、创作者、地区、年代、案件状态、一句话简介
故事视图：故事摘要、完整故事、人物关系、角色档案(2-4人)、关键时间线、结局/真相

  - 游戏平台：[PC/PS/Xbox/Switch/手机/VR/其他]
  - 玩法类型：[文字冒险/推理解谜/动作推理/开放世界推理/桌游改编/互动电影/其他]

  - 关卡结构：[描述整体关卡/章节结构]
  - 玩家引导方式：[描述如何引导玩家]
  - 可复用游戏模板：[1-2个，对应任务5的模板库]

1. 用 Python 脚本生成6个案例的 JSON 数据

3. 批量创建线索链到子表
4. 同步到本地 JSON
5. 验证：网站显示、字段完整、线索链关联

## 五、执行顺序与依赖关系

```
任务1（扩充游戏案例）──┐
                      ├──→ 任务4（诡计映射表）──→ 任务5（游戏模板库）
任务2（完善游戏字段）──┘

**建议执行顺序**：任务1 → 任务2 → 任务3 → 任务4 → 任务5

## 七、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| 飞书 Base 字段不支持 JSON 格式 | 改编建议无法结构化存储 | 用多行文本存储 JSON 字符串，前端解析 |
| 游戏案例信息不准确 | 数据质量问题 | 每个案例附参考链接，标注信息来源 |
| 工作量超出预期 | 时间延长 | 优先完成 P0 任务（任务1+2），P1/P2 可后续补充 |
| 模板设计过于抽象 | 实际参考价值低 | 每个模板绑定至少2个真实案例作为参考 |
