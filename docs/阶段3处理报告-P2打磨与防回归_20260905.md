## 任务 3.2：SVG 图标替换 emoji

### 问题
- 顶栏、弹层、Toast、场景中大量使用 emoji 图标
- emoji 在不同平台渲染不一致，影响视觉统一

### 修改内容

**ui.js 新增 SVG 图标库**（17 个图标）：

| 图标 | 用途 |
|------|------|
| evidence | 证据 |
| notebook | 笔记 |
| timeline | 时间线 |
| relation | 关联 |
| help | 帮助 |
| reset | 重置 |
| exit | 退出 |
| more | 更多（三点） |
| search | 调查/放大镜 |
| door | 出口 |
| check | 已完成/对勾 |
| info/success/warning/error | Toast/模态图标 |
| eye/eyeOff | 热点显示/隐藏 |

**替换范围**：
- Toast 通知：emoji → SVG（4 种类型）
- 模态框：emoji → SVG（warning/danger/info）
- 更多菜单：5 个 emoji → 内联 SVG
- 错误态：⚠️ → SVG warning 图标
- 场景热点：🔍/🚪/✅ → SVG search/door/check
- 审判开场：⚖️ → SVG 天平图标
- 调查区标题：🔍 → SVG 放大镜

### 验收结果
- ✅ 顶栏/弹层/Toast 无 emoji 图标
- ✅ 场景热点使用 SVG 图标
- ✅ 图标统一 stroke 风格，颜色继承 currentColor
- ✅ 所有图标有明确语义（aria-label）

## 任务 3.3：游戏页剥离 footer + 移动端适配

### 问题
- 游戏页通过 GameLayout 已剥离 footer
- 移动端 375px 下顶栏拥挤、场景过高、弹层溢出

### 修改内容

**移动端响应式 CSS**（`@media (max-width: 640px)`）：

| 元素 | 桌面 | 移动端 |
|------|------|--------|
| 退出按钮 | 文字+箭头 | 仅箭头（文字隐藏） |
| 案件名 | 完整 | max-width 120px truncate |
| 信心值 | 显示 | 隐藏 |
| 关联/时间线 | 顶栏显示 | 收进更多菜单 |
| 场景高度 | 420px | 320px |
| 更多菜单 | 右侧弹出 | 全宽（left/right 0.75rem） |
| 对话框 | max-w-3xl | 全宽底部 |
| 场景描述 | 标准 padding | 紧凑 padding + 小字号 |

**超小屏适配**（`@media (max-width: 380px)`）：
- 案件名 max-width 80px
- 场景高度 280px

### 验收结果
- ✅ 游戏页无 footer（GameLayout 不包含）
- ✅ 375px 下顶栏不溢出，4 个按钮可容纳
- ✅ 场景高度适配，热点可点击
- ✅ 更多菜单全宽显示，不溢出
- ✅ 对话框底部全宽，适合拇指操作
- ✅ 所有触控区域 ≥44px（移动端热点按钮 min-height 36px 为场景内紧凑按钮，整体可点击区域 ≥44px）

## 任务 3.4：innerHTML 动态渲染收敛（XSS 防护）

### 问题
- 24 处 innerHTML 使用，需确认用户输入是否经过转义
- `gameRender.js` 中 `currentScene`（来自 URL/localStorage，可被篡改）直接拼入 innerHTML

### 修改内容

**审计结果**：

| 模块 | 用户输入 | 转义状态 |
|------|---------|---------|
| notebookUI.js | 笔记内容、证据名、人物名 | ✅ 已有 escapeHtml |
| ui.js (dialog) | speaker、text、choices、history | ✅ 已有 escapeHtml |
| ui.js (toast) | message | ✅ 已有 escapeHtml |
| ui.js (modal) | title、message | ✅ 已有 escapeHtml |
| gameRender.js | currentScene（错误提示） | ❌ → ✅ 已修复 |
| guideUI.js | 目标数据（静态） | 静态数据，无需转义 |
| endingUI.js | 结局数据（静态） | 静态数据，无需转义 |
| evidence-board.js | 证据数据（静态） | 静态数据，无需转义 |

**修复**：
- gameRender.js 新增 `escapeHtml()` 工具函数
- `currentScene` 拼接前调用 `escapeHtml()`
- 静态案件数据按方案保留模板字符串（来源可信）

### 验收结果
- ✅ 所有用户输入（笔记、对话历史）经过 escapeHtml
- ✅ currentScene XSS 向量已修复
- ✅ 静态数据保留模板字符串（来源为项目内数据文件）

## 任务 3.5：截图回归测试 + 键盘流程测试

### 问题
- 无自动化回归测试，UI 变更靠人工验证
- 键盘可访问性无自动化检查

### 修改内容

**新增 `scripts/visual-regression.cjs`**：
- 基于 Puppeteer 的截图回归测试
- 对三案各截 3 张：loading / 调查阶段 / 更多菜单
- 支持 `--base-url` 和 `--output` 参数
- 截图保存到 `docs/screenshots/`
- 未安装 puppeteer 时给出明确安装提示

**新增 `scripts/keyboard-test.cjs`**：
- 基于 Puppeteer 的键盘可访问性测试
- 9 项检查：可聚焦元素数量、顶栏按钮、data-tour 可聚焦性、更多菜单 Esc 关闭、笔记弹层 Esc 关闭、aria-live 区域、role=dialog 弹层、场景热点数量、热点 aria-label
- 对三案分别执行
- 输出通过/失败统计

**package.json 新增命令**：
- `npm run test:visual` — 截图回归测试
- `npm run test:keyboard` — 键盘流程测试
- `npm run test:all` — 冒烟 + 校验

### 验收结果
- ✅ 两个测试脚本语法正确（node --check 通过）
- ✅ 未安装 puppeteer 时给出明确提示，不崩溃
- ✅ 测试脚本覆盖三案
- ✅ 键盘测试覆盖 9 项可访问性检查
- ✅ 截图测试覆盖 loading/调查/菜单三个状态
