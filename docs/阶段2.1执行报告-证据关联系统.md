## 一、功能概述

证据关联系统是推理游戏的**核心玩法**：玩家不再是被动收集证据，而是主动思考证据之间、证据与证人之间的关联，通过"连线"发现矛盾点。

这对应codex建议的"用户能验证至少一个核心推理动作，而不是只浏览文本"。

## 二、实现内容

### 2.1 证据板UI（evidence-board.js）

**入口**：顶部栏新增"🔗 关联"按钮（紫色）

**界面结构**：
- 头部：标题 + 已发现关联计数（X/5）
- 选择提示栏：实时显示当前选择状态
- 证据区：已收集证据的卡片网格（5列）
- 证人区：已询问证人的卡片网格（6列）
- 已建立关联列表：显示所有成功/自定义关联
- 底部：提示 + 清除选择按钮

### 2.2 关联交互流程

```
点击第一个物品（高亮）→ 点击第二个物品 → 自动判断关联
     ↓
  ┌──┴──┐
  ↓     ↓
成功   失败（但保存为自定义关联）
  ↓     ↓
显示推理结论  提示"暂时没有直接关联"
增加信心值    保存到玩家笔记
记录到笔记    鼓励后续探索
```

**交互细节**：
- 点击已选中的物品可取消选择
- 选中状态有高亮边框和背景
- 关联成功有庆祝动画（模态框）
- 重复发现已有关联会提示"已经发现过"

### 2.3 预设关联（5条）

基于东方快车的矛盾点设计：

| ID | 关联组合 | 推理结论 | 信心值 |
|----|----------|----------|--------|
| link-watch-conductor | 怀表 ↔ 列车员 | 怀表停在1:15，列车员说1:15听到动静，时间吻合 | +20 |
| link-handkerchief-hubbard | 手帕 ↔ 赫伯德夫人 | 手帕H字母与Hubbard姓氏首字母吻合 | +15 |
| link-ash-mary | 烟灰 ↔ 玛丽 | 现场有香烟灰，受害者只抽雪茄，玛丽说睡得沉 | +20 |
| link-handkerchief-pincess | 手帕 ↔ 公主 | 俄文H对应N，公主教名娜塔莉亚首字母N | +25 |
| link-window-body | 窗户 ↔ 尸体 | 窗户大开但雪地无脚印，伪造逃走路线 | +15 |

### 2.4 玩家数据持久化

**PlayerData新增**：
- `evidenceLinks` 数组：存储所有关联（成功+自定义）
- `addEvidenceLink(linkData)`：添加关联（自动去重）
- `getEvidenceLinks()`：获取所有关联
- `clearEvidenceLinks()`：清空关联

**关联数据结构**：
```javascript
{
  presetId: 'link-watch-conductor',  // 预设ID（自定义关联无此字段）
  from: 'watch',                     // 第一个物品ID
  to: 'conductor',                   // 第二个物品ID
  fromType: 'evidence',              // 类型：evidence/witness
  toType: 'witness',
  isCorrect: true,                   // 是否为预设成功关联
  title: '时间矛盾',                  // 成功关联的标题
  conclusion: '...',                 // 推理结论
  confidence: 20,                    // 增加的信心值
  timestamp: 1234567890              // 建立时间
}
```

### 2.5 与笔记系统联动

- 成功关联**自动记录**到推理笔记板的"推理"栏
- 笔记内容格式：`【关联标题】推理结论`
- 重要度评分 = 信心值/5（4-5星）
- 玩家可以在笔记中进一步编辑

### 2.6 信心值系统

- 成功关联增加信心值（+15~+25）
- 信心值上限100
- 顶部栏实时显示
- 信心值影响审判阶段的说服力（后续阶段实现）

## 五、设计决策

### 决策1：证据+证人混合关联
**选择**：证据板同时展示证据和证人，支持任意两个物品关联
**理由**：东方快车的矛盾点主要是证据与证词的矛盾，只做证据-证据关联会限制玩法
**替代方案**：只做证据-证据关联（更纯粹，但不符合本案数据）

### 决策2：失败关联也保存
**选择**：关联失败时仍保存为"自定义关联"，并提示"也许后续会发现联系"
**理由**：
- 鼓励玩家探索，不惩罚错误尝试
- 符合侦探"记录所有可能性"的工作方式
- 后续可以实现"自定义关联被证实"的反转玩法

### 决策3：点击选择而非拖拽
**选择**：点击选择两个物品进行关联
**理由**：
- 实现简单可靠，移动端友好
- 方案文档中已确认"先做方案B验证玩法，后续再升级为拖拽"
- 拖拽在证据卡片较多时容易误操作

### 决策4：信心值作为关联奖励
**选择**：成功关联增加信心值
**理由**：
- 给玩家即时正向反馈
- 信心值后续影响审判说服力，形成闭环
- 比单纯"解锁内容"更有成就感

## 六、已知限制与后续优化

### 当前限制
1. 预设关联只有5条，全部发现后玩法耗尽
2. 关联是二元判断（成功/失败），没有"部分正确"
3. 自定义关联没有备注功能（虽然数据结构预留了note字段）
4. 没有关联的可视化图谱（只是列表展示）

### 后续优化方向
1. **阶段2.4审判重构**：信心值影响审判选项和结局
2. **关联图谱可视化**：用SVG/Canvas展示证据关系网
3. **自定义关联备注**：允许玩家给失败关联添加备注
4. **部分正确关联**：某些组合接近但不完全正确，给出提示
5. **拖拽连线**：后续升级交互方式
6. **关联提示系统**：卡关时给出"这两个物品可能有关联"的提示
