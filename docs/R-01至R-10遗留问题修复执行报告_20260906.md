## R-02：存档恢复机制

**状态**：✅ 完成

**修改文件**：
- `src/game/gameState.js`
- `src/game/gameRender.js`

**问题**：原逻辑只有 URL 含 `continue=1` 才读存档，其他情况直接 `localStorage.removeItem(SAVE_KEY)` 删除存档，导致用户刷新页面后进度丢失。

**修复方案**：

1. **gameState.js init()**（第 223-241 行）：
   - 移除无条件删除存档的逻辑
   - 新增三分支：
     - `continue=1` + 有存档 → 恢复存档
     - `reset=1` → 删除存档，重新开始
     - 有存档但未明确选择 → 设置 `state.pendingSaveChoice = true`，暂停等待用户选择

2. **新增方法**：
   - `getSaveInfo()` — 读取存档摘要（阶段、证据数、证人数）
   - `continueSavedGame()` — 恢复存档并继续渲染
   - `resetSavedGame()` — 清除存档并重置到初始状态

3. **gameRender.js render()**（第 58-61 行）：
   - 检测 `pendingSaveChoice` 时调用 `showSaveChoiceModal()`，不渲染游戏内容

4. **新增 showSaveChoiceModal()**：
   - 显示存档摘要（阶段、已收集证据/证人数量）
   - 两个按钮：「继续游戏」「重新开始」
   - 使用现有 `GameUI.showModal` 组件

5. **save() 保护**：`pendingSaveChoice` 为 true 时不写入存档，避免空状态覆盖

**验证**：语法检查通过，冒烟测试同步检查通过。

## R-07：关联板卡片语义化为 button

**状态**：✅ 完成

**修改文件**：`src/game/evidence-board.js`

**问题**：证据/证人卡片使用 `<div onclick>`，无法通过键盘操作，无 ARIA 选中态。

**修复方案**：

1. **证据卡片**（第 128-137 行）：
   - `<div>` → `<button>`
   - 添加 `aria-pressed="false"` `aria-label="证据：xxx"`
   - 添加 `focus:outline-none focus-visible:ring-2 focus-visible:ring-amber-500` 焦点样式
   - `text-left` 保持文字左对齐

2. **证人卡片**（第 142-151 行）：
   - 同上，`aria-label="证人：xxx"`

3. **selectItem() 选中态**（第 218 行）：
   - 选中时设置 `element.setAttribute('aria-pressed', 'true')`

4. **clearSelection()**（第 242 行）：
   - 取消选中时设置 `aria-pressed="false"`

**效果**：
- Tab 键可聚焦卡片
- Enter/Space 可触发选择（button 默认行为）
- 屏幕阅读器可播报选中状态
- 焦点环可见

**验证**：语法检查通过。
