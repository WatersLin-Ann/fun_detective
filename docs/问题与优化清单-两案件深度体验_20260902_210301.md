## 二、P0 致命问题（阻断游玩）

### P0-1 线上部署版本严重落后，审判流程直接缺失
- **现象**：线上 `window.GameInteractions`、`window.GuideUI` 为 `undefined`；`__startQuestioning`、`__goToClosing`、`__object`、`__verdictChoose`、`__closeEnding` 五个审判函数全部不存在。审判开场点"开始质询"无任何反应，永远卡在开场。
- **根因**：本地多轮迭代（审判重构、引导系统、模块拆分）未同步推送到 GitHub，线上是旧版 `gameInteractions.js`。
- **位置**：线上 `game/gameInteractions.js`（旧）；对照本地 `src/game/gameInteractions.js:409/417/436`。
- **修复方案**：
  1. 先修完本清单所有本地代码问题；
  2. `src/game/*.js` 全量同步到 `public/game/`；
  3. `npm run build` 验证后提交并推送 GitHub，确认 Actions/Pages 部署完成；
  4. 线上强刷（Ctrl+F5）复验五个函数均为 function。

### P0-2 进入调查阶段的初始场景被硬编码为 'corridor'
- **现象**：血字的研究开场结束后调查场景**完全空白**；其首个调查场景是 `crime-scene`，根本没有 `corridor`。
- **根因**：`__introContinue` 里写死 `currentScene = 'corridor'`（东方快车的场景 id）。
- **位置**：`src/game/gameInteractions.js:49`。
- **修复方案**：改为从案件数据动态取首个可调查场景。建议在每个案件 `meta` 增加 `firstScene` 字段（如东方快车 `corridor`、血字 `crime-scene`、逆转 `courtroom`），代码改为：
  ```js
  GameState.state.currentScene = window.GameData?.meta?.firstScene
    || GameState.getGameData().gameScenes.find(s => s.id !== 'intro')?.id
    || GameState.getGameData().gameScenes[0]?.id;
  ```
  并对数组/对象两种 scenes 结构做兼容（见 P0-5）。

### P0-3 逆转裁判 scenes 是对象而非数组，渲染直接抛错
- **现象**：逆转裁判任何用到 `scenes.map/find` 的地方报 `scenes.map is not a function`，调查阶段无法渲染。
- **根因**：东方快车、血字的研究 `scenes` 是**数组**；逆转裁判是**对象** `{intro, courtroom, witness}`，且每个场景**没有 `interactables` 和 `exits` 字段**。
- **位置**：`src/game/data-phoenix-wright.js:24`（`const scenes = {`）。
- **修复方案（二选一，推荐 A）**：
  - **A. 数据对齐引擎契约**：把逆转裁判 scenes 改为数组，每个场景补齐 `interactables: []`、`exits: []`、`sceneType`、`background`，证据/证人以 interactable 形式挂到对应场景。
  - B. 引擎兼容两种结构：在 `gameState.init` 统一把对象 scenes 转成数组（`Object.values`），并在 render 层对缺失 interactables/exits 做兜底。
  - 长期应固化《案件数据 Schema 文档》，新增案件用校验脚本卡点。

### P0-4 逆转裁判开场对话是对象数组，直接显示 [object Object]
- **现象**：逆转裁判开场文本渲染为 `[object Object]`。
- **根因**：其 `dialogs.intro` 元素是 `{speaker, color, text}` 对象，而 `renderIntro` 用 `textContent = texts[idx]`，对象被强转成 `[object Object]`。东方快车/血字是纯字符串数组。
- **位置**：`src/game/data-phoenix-wright.js:134-139`；渲染处 `src/game/gameRender.js renderIntro`。
- **修复方案**：
  - 统一对话格式。推荐引擎同时支持两种：若元素是对象，取 `.text`（并可选渲染 speaker/color），若是字符串直接显示；
  - 或把逆转裁判 intro 改写为带角色前缀的字符串数组，与其他案件一致。
  - 已在 renderIntro 加了非字符串兜底转换，但数据层仍应统一。

### P0-5 逆转裁判缺少 investigationStart，且开场段数与引擎推进逻辑不符
- **现象**：通用引擎按"intro 6 段 + investigationStart 6 段 = 12 段后进入调查"推进；逆转裁判 intro 仅 4 段且**没有 investigationStart**，点到第 5 段开始空白，第 7 段访问 undefined 报错。
- **位置**：`src/game/data-phoenix-wright.js:133-154`；推进逻辑 `gameInteractions.js:46-51`、`gameRender.js renderIntro`（写死 `<6 / >=6 / >=11 / >=12`）。
- **修复方案**：
  1. 引擎不要写死 6/12 段数，改为 `intro.length`、`investigationStart.length` 动态计算；
  2. 逆转裁判补齐 `investigationStart`（或显式声明开场结束即进入下一阶段）；
  3. 见 P1-8，逆转裁判本质是"纯法庭"游戏，流程需单独适配。

## 三、P1 严重问题（内容张冠李戴）

### P1-1 审判开场文案硬编码为东方快车
- **现象**：血字的研究审判开场竟显示"现在开始审理**东方快车谋杀案**。受害者**塞缪尔·雷切特**……身中**12刀**……**12名乘客**之中。**波洛先生**请开始质询"。
- **位置**：`src/game/gameRender.js:236、239`（renderTrialOpening 写死）。
- **修复方案**：案件数据新增 `trialOpening: [段落1, 段落2]`（或 `meta.trialIntro`），renderTrialOpening 改为遍历数据渲染；无配置时用通用模板（用 `meta.name / meta.victim / meta.detective` 拼接）。

### P1-2 进入审判的目标场景硬编码 'dining-car'
- **现象**：进入审判时写死 `currentScene='dining-car'`，且 `__exit` 仅在 `sceneId==='dining-car'` 时弹审判确认。逆转裁判无 dining-car，无法进入审判；血字虽有同名场景但语义是"审判室"，命名混乱。
- **位置**：`gameInteractions.js:131、142`。
- **修复方案**：`meta` 增加 `trialScene` 字段（东方快车/血字 `dining-car`、逆转 `courtroom`），代码统一读配置；场景命名建议改为语义中性的 `trial-room`。

### P1-3 进入审判门槛硬编码"≥3 证据 + ≥2 证人"
- **位置**：`gameInteractions.js:132`。
- **修复方案**：门槛移入 `meta.trialRequirement = { minEvidence: 3, minWitnesses: 2 }`，按案件配置；逆转裁判这类纯法庭案件可设为 0/0 直接开庭。

### P1-4 "前往餐车进行审判"等文案硬编码
- **位置**：`gameInteractions.js:135`（确认弹窗 message）。
- **修复方案**：文案按 `meta.trialSceneName`（餐车/审判室/法庭）动态生成。

### P1-5 证人颜色映射硬编码东方快车证人 id
- **现象**：血字、逆转的证人 id 不在硬编码表中，全部回退灰色，数据里已配的 `witness.color` 未被使用。
- **位置**：`gameInteractions.js:95-103`。
- **修复方案**：优先读 `witness.color`，其次读案件数据导出的 `witnessColors`，最后才用默认色：
  ```js
  const color = witness.color
    || GameState.getGameData().gameData?.witnessColors?.[witness.id]
    || '#94a3b8';
  ```

### P1-6 笔记导出标题硬编码"东方快车谋杀案"
- **位置**：`src/game/playerData.js:253`。
- **修复方案**：改为 `window.GameData?.meta?.name || '推理案件'`。

### P1-7 浏览器标签页标题（BaseLayout title）硬编码
- **现象**：玩血字/逆转时标签页仍显示"东方快车：推理审判"。
- **位置**：`src/pages/game-design/prototype/play.astro:10`。
- **修复方案**：Astro 端无法直接读运行时案件名，可在初始化 JS 里 `document.title = caseName + ' | Fun Detective'`。

### P1-8 逆转裁判游戏类型与引擎流程根本不匹配（需决策）
- **现象**：逆转裁判是"纯法庭对抗"（证据法定、直接开庭、逐句证词追问→异议），但当前引擎是"先自由探索收集证据→再审判"。其 scenes 无探索交互、证据靠 `scene` 字段标记而非现场拾取。
- **修复方案（需你拍板）**：
  - 方案 A（推荐，快）：把逆转裁判改造成符合现有引擎——补一个简短"庭前调查"场景承载证据收集，再进入法庭审判；
  - 方案 B（长期，强）：引擎支持案件声明 `flowType: 'investigation-trial' | 'courtroom-only'`，纯法庭案件跳过调查阶段，直接进入质询，证据在开庭时全部预置进证据栏。

## 四、P2 一般问题（交互与健壮性）

### P2-1 收集证据回调引用全局 event，程序化调用报错且动画位置错误
- **现象**：`GameUI.collectEvidence()` 内部回调执行到 `event.target.getBoundingClientRect()` 时，若没有真实点击事件会抛 `Cannot read properties of undefined (reading 'target')`，导致收集中断；真实点击时 event.target 是"加入证据栏"按钮，收集动画从按钮飞出而非场景中的证据图标。
- **位置**：`gameInteractions.js:81`。
- **修复方案**：在 `__interact` 触发时先记录被点元素坐标并闭包传入回调，不依赖全局 event；回调签名改为 `(evidence, sourceRect)=>{}`，移除对全局 event 的引用。

### P2-2 弹层入场动画依赖 requestAnimationFrame，后台标签/渲染延迟时永久不可见
- **现象**：证据卡片初始 `opacity-0 scale-95`、对话框初始 `translate-y-full`，靠 rAF 移除；当页面处于 hidden（后台标签）或 rAF 被节流时，弹层永远停在透明/屏幕外，表现为"点了没反应"。
- **位置**：`ui.js:134`（对话框）、`ui.js:317`（证据卡片）。
- **修复方案**：改用 CSS `@keyframes` 入场动画（不依赖 JS 帧回调），或 rAF + setTimeout 双保险，并在显示时同步移除 `opacity-0/translate-y-full` 初始类。

### P2-3 打字机效果期间无选项且缺少"点击跳过"提示
- **现象**：证人证词约 2.5 秒逐字输出，打完才出现"追问/继续"，期间用户以为卡住；虽然点文本可跳过，但无提示。
- **位置**：`ui.js:143-166`。
- **修复方案**：打字期间在右下角显示"点击文本快进 ▸"提示；或选项容器先渲染但禁用，打字结束激活。

### P2-4 loadCaseData 案件数据串台（本地已修，待部署）
- **现象/修复**：切换案件时旧 `window.GameData` 残留会造成标题与内容不一致。已在本地 `gameState.js loadCaseData` 加：加载前置空、加载后校验 meta.id 匹配、script url 加 `?v=时间戳` 防缓存、防重复加载。**需随 P0-1 一起部署生效**。

### P2-5 IIFE 全局变量命名不统一，存在重复声明隐患
- **现象**：东方快车 `const CaseData_orientExpress`、血字 `const CaseData_studyInScarlet`、逆转 `const GameData`（通用名）。若未来同一页加载多个案件，`const GameData` 易撞名报 `Identifier already declared`。
- **修复方案**：统一为 `const CaseData_<camelCaseId>`，末尾统一 `window.GameData = CaseData_xxx`，不使用裸 `GameData` 全局 const。

### P2-6 meta 字段名不统一（name vs title）
- **现象**：东方快车/血字用 `meta.name`，逆转用 `meta.title`。
- **修复方案**：统一为 `meta.name`；渲染层兼容读取已加（`name||title`），但数据层应对齐。

### P2-7 证据字段不统一（foundIn/keyInfo vs scene/icon/detail）
- **现象**：逆转证据用 `scene/icon/detail`，引擎证据卡读 `foundIn`（缺失时显示默认"犯罪现场"）与 `keyInfo`（缺失时"查看细节"为空）。
- **修复方案**：统一证据 Schema：`foundIn / keyInfo / icon`；或渲染层做字段别名兼容。

### P2-8 证人结构不统一（嵌套 contradiction、缺 followUpTestimony）
- **现象**：逆转证人把矛盾写成嵌套 `witness.contradiction`，且部分证人无 `followUpTestimony`（追问按钮缺失）；引擎用顶层 `contradictions` 数组 + `followUpTestimony`。
- **修复方案**：统一为顶层 contradictions 数组；确无追问的证人显式 `followUpTestimony: null`，引擎据此隐藏"追问"按钮（当前已能处理 null，但数据要显式声明）。

## 五、音频专项（用户明确要求：提供真实音乐前不得发声）

### 音频处理结果（本次已完成，待部署验证）
- **问题**：原 `audioManager.js` 用 Web Audio API 合成占位 BGM/SFX 且默认 `autoPlayBgm:true、masterVolume:0.7`，进入游戏即自动发声。
- **已做修改**：
  1. `audio-config.js` 新增总开关 `settings.audioEnabled = false`，并保留 `masterVolume:0 / autoPlayBgm:false`；
  2. `audioManager.js` 在 `init / playTone / playBgm / playSfx` 四个入口最前面判断总开关，关闭时**直接 return，不创建 AudioContext、不启动循环、不发任何声**；
  3. `gameRender.js updateTopBar` 在总开关关闭时**隐藏顶部 🔊 音量按钮**，避免误解；
  4. 架构完整保留：未来你把真实音频放到 `public/game/audio/bgm|sfx/`，只需把 `audioEnabled` 置 true 并补文件映射即可，无需改引擎。
- **待办**：随 P0-1 部署后，线上三个案件逐一确认全程无声、无音量按钮。

## 六、P3 体验优化建议（不紧急）

1. **案件数据 Schema 文档 + 校验脚本**：写一份 `docs/案件数据Schema.md`，并加 `scripts/validate-case.js`（检查 scenes 为数组、dialogs 段数、矛盾引用完整性、字段齐全），新增案件先跑校验，从源头杜绝 P0-3/P0-4/P0-5 这类结构问题。
2. **案件选择页标注流程类型**：探索推理型 / 纯法庭型，让玩家有预期。
3. **审判阶段补"证据-证词"高亮联动**：出示正确证据时，对应证词文本高亮，逻辑感更强。
4. **火柴人/场景背景按 sceneType 统一**：逆转裁判的 `background:'courtroom'` 是语义字符串，需在 sceneBgs 映射中补法庭素材。
5. **全局错误边界**：渲染层 try-catch，任一模块异常时在页面给出可见报错与"返回选案/重置"按钮，而不是白屏或静默无响应。
6. **本地→public 同步自动化**：已有的 `scripts/sync-game-js.js` 应在 build 前自动执行（package.json 的 build 脚本前置），避免再次出现"src 已改、public 仍旧、线上缺函数"。
