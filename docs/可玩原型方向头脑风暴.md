## 二、方向1：密室逃脱原型

### 2.1 核心概念
**《十角馆：逃离》** - 基于《十角馆事件》的密室逃脱游戏

### 2.2 玩法设计
- **场景**：十角馆的7个房间，每个房间是一个独立密室
- **核心循环**：
  1. 进入房间，发现同伴"死亡"
  2. 搜索房间，收集线索和道具
  3. 破解房间机关（密码锁、隐藏门、机关盒）
  4. 进入下一个房间
  5. 最终发现真凶，逃出十角馆

### 2.3 创新点
- **十角馆建筑诡计**：利用十角形建筑的特殊结构，房间之间有隐藏通道
- **身份诡计**：玩家以为在和NPC对话，实际是凶手在引导
- **多结局**：
  - 结局A：发现真相，被凶手"杀死"（坏结局）
  - 结局B：利用机关反杀凶手（好结局）
  - 结局C：放火烧馆，与凶手同归于尽（原作结局）

### 2.4 技术实现
- **难度**：⭐⭐⭐（中等）
- **关键技术**：房间切换系统、物品栏、机关解谜逻辑、多结局分支
- **复用组件**：GameScene、EvidenceBar（可改造为物品栏）
- **预计开发量**：3-5天

### 2.5 适合案例
- 十角馆事件（首选）
- 无人生还（孤岛模式）
- 钟表馆事件（建筑机关）
- 本阵杀人事件（日式密室）

## 三、方向2：连环案件原型

### 3.1 核心概念
**《开膛手杰克：伦敦追凶》** - 基于开膛手杰克案件的连环案件追踪游戏

### 3.2 玩法设计
- **场景**：1888年伦敦白教堂区，多个犯罪现场
- **核心循环**：
  1. 接到报案，前往犯罪现场
  2. 调查现场，收集证据（尸体、物证、目击者）
  3. 回到警局，分析证据，建立案件关联
  4. 预测下一次犯罪时间和地点
  5. 部署警力，试图阻止犯罪
  6. 最终锁定嫌疑人

### 3.3 创新点
- **案件关联系统**：通过MO（作案手法）、受害者特征、地理位置建立案件关联
- **犯罪预测**：基于证据预测下一案，预测正确可以阻止，错误则继续发生
- **时间线推进**：游戏内时间流动，玩家需要在有限时间内破案
- **历史沉浸**：真实历史背景，维多利亚时代伦敦氛围

### 3.4 技术实现
- **难度**：⭐⭐⭐⭐（较难）
- **关键技术**：案件关联算法、地图系统、时间推进机制、犯罪预测逻辑
- **复用组件**：EvidenceBar、TrialPanel（可改造为分析面板）
- **预计开发量**：5-7天

### 3.5 适合案例
- 开膛手杰克（首选）
- 十二宫杀手（密码破译）
- 华城连环杀人案（杀人回忆原型）
- 白银连环杀人案
- 山姆之子

## 四、方向3：叙事解谜原型

### 4.1 核心概念
**《禁闭岛：意识迷宫》** - 基于《禁闭岛》的多视角叙事解谜游戏

### 4.2 玩法设计
- **场景**：禁闭岛精神病院，多个视角切换
- **核心循环**：
  1. 以主角视角探索岛屿，收集记忆碎片
  2. 切换到其他角色视角，获取不同信息
  3. 拼接记忆碎片，还原事件真相
  4. 发现主角身份的真相
  5. 选择结局：接受真相 or 继续幻想

### 4.3 创新点
- **不可靠叙述者**：主角的记忆本身就是最大的谜题
- **多视角叙事**：不同角色看到的"真相"不同
- **记忆碎片系统**：收集的碎片可以拼接，拼出完整画面
- **元叙事**：游戏本身就是治疗的一部分
- **双结局**：
  - 结局A：接受治疗，承认自己是凶手（悲剧结局）
  - 结局B：拒绝接受，继续作为"执法者"（幻觉结局）

### 4.4 技术实现
- **难度**：⭐⭐⭐⭐（较难）
- **关键技术**：视角切换系统、记忆碎片拼接、叙事分支、多结局
- **复用组件**：DialogBox、GameScene
- **预计开发量**：5-7天

### 4.5 适合案例
- 禁闭岛（首选）
- 致命ID（人格分裂）
- 记忆碎片（倒叙叙事）
- 穆赫兰道（梦境与现实）
- 罗杰疑案（叙述性诡计）

## 五、方向4：限时破案原型

### 5.1 核心概念
**《24小时：列车炸弹》** - 原创限时破案游戏（可结合《点与线》时刻表诡计）

### 5.2 玩法设计
- **场景**：行驶中的列车/封闭空间，倒计时24小时（游戏内1小时=现实1分钟）
- **核心循环**：
  1. 收到威胁：列车上有炸弹，24小时内找出凶手和炸弹
  2. 在列车各车厢搜索，收集线索
  3. 询问乘客，发现矛盾
  4. 排除嫌疑人，缩小范围
  5. 在倒计时结束前找出炸弹位置和凶手
  6. 拆除炸弹，揭露真相

### 5.3 创新点
- **实时倒计时**：游戏内时间持续流逝，增加紧迫感
- **时刻表诡计**：利用列车时刻表制造不在场证明
- **空间限制**：只能在列车内活动，每个车厢有不同线索
- **压力决策**：时间不够时需要选择优先调查方向
- **多结局**：
  - 结局A：成功拆除炸弹，抓住凶手（完美结局）
  - 结局B：抓住凶手但炸弹爆炸（部分成功）
  - 结局C：时间耗尽，炸弹爆炸（失败结局）

### 5.4 技术实现
- **难度**：⭐⭐⭐（中等）
- **关键技术**：倒计时系统、车厢切换、时间触发事件、多结局
- **复用组件**：EvidenceBar、TrialPanel、GameScene
- **预计开发量**：3-5天

### 5.5 适合案例
- 点与线（时刻表诡计，首选）
- 东方快车谋杀案（封闭空间）
- 阳光下的罪恶（限时破案）
- 控方证人（法庭限时）

## 六、优先级建议

### 6.1 推荐制作顺序

| 优先级 | 原型名称 | 模板 | 理由 |
|--------|----------|------|------|
| P0 | 《十角馆：逃离》 | 密室逃脱 | 技术难度中等，与已有原型差异大，建筑诡计有视觉冲击力 |
| P1 | 《24小时：列车炸弹》 | 限时破案 | 倒计时机制简单有效，复用现有组件多，开发周期短 |
| P2 | 《禁闭岛：意识迷宫》 | 叙事解谜 | 叙事深度高，但开发难度大，适合作为第二个重点项目 |
| P3 | 《开膛手杰克：伦敦追凶》 | 连环案件 | 系统最复杂，开发周期长，适合作为长期项目 |

### 6.2 快速验证方案

如果想快速验证某个方向，可以先做"最小可行原型"：
- **密室逃脱**：先做1个房间，验证机关解谜逻辑
- **连环案件**：先做2个案件，验证案件关联系统
- **叙事解谜**：先做2个视角，验证视角切换和碎片拼接
- **限时破案**：先做30分钟倒计时，验证时间压力机制

## 七、技术架构建议

### 7.1 通用游戏框架
基于已有原型，抽象出通用游戏框架：
```
GameEngine
├── SceneManager（场景管理）
├── InventorySystem（物品/证据系统）
├── DialogSystem（对话系统）
├── TimeSystem（时间系统，限时破案用）
├── PuzzleSystem（解谜系统，密室逃脱用）
└── EndingManager（结局管理）
```

### 7.2 数据驱动
所有游戏内容用JSON配置：
- 场景配置：场景名称、出口、可交互物品
- 对话配置：说话人、文本、选项、触发条件
- 解谜配置：谜题类型、答案、奖励
- 结局配置：触发条件、结局文本

### 7.3 组件复用
已有4个组件可复用：
- GameScene → 场景渲染
- EvidenceBar → 物品栏/证据栏
- DialogBox → 对话框
- TrialPanel → 分析面板/操作面板

---

## 八、总结

4个新原型方向各有特色：
- **密室逃脱**：视觉冲击力强，机关解谜有趣
- **连环案件**：系统深度高，历史沉浸感强
- **叙事解谜**：叙事深度高，情感冲击力强
- **限时破案**：紧张刺激，开发周期短

建议优先制作**《十角馆：逃离》（密室逃脱）**，与已有推理审判原型形成互补，验证不同游戏类型的可行性。

用户可以选择：
1. 按推荐顺序逐个制作
2. 指定某个方向优先制作
3. 先做某个方向的最小可行原型验证
