## 一、系统目标

### 核心价值
1. **增强探索感**：玩家在笔记中写下推理关键词，可以解锁隐藏内容
2. **奖励深度思考**：鼓励玩家主动记录推理，而不是被动收集
3. **增加 replay value**：不同关键词解锁不同内容，多次游玩有新发现
4. **与笔记系统联动**：充分利用已有的笔记系统，增加其价值

### 设计理念
- 玩家在笔记的"线索"、"推理"、"待验证"三栏中输入内容
- 系统检测输入内容中是否包含预设关键词
- 检测到关键词后，解锁隐藏对话、线索或增加信心值
- 已解锁的关键词在笔记UI中显示，玩家可以查看解锁了什么

## 二、数据结构设计

### 2.1 案件数据中的关键词配置

在案件数据文件中添加`noteKeywords`字段：

```javascript
noteKeywords: [
  {
    id: 'kw-001',
    keyword: '12人',           // 检测关键词
    aliases: ['十二人', '12个人', '十二个人'],  // 别名（也会触发）
    category: '推理',          // 分类：推理/线索/待验证
    unlockType: 'dialog',      // 解锁类型：dialog/clue/confidence
    unlockContent: {
      speaker: '波洛',
      text: '你注意到了吗？车厢里正好有12名乘客，而陪审团也正好是12人...这不是巧合。',
      confidence: 10
    },
    description: '12人与陪审团的联系',  // 解锁后显示的描述
    discovered: false
  }
]
```

### 2.2 玩家状态


## 三、功能设计

### 3.1 关键词检测时机

#### 触发时机
1. **添加线索时**：在笔记的"线索"栏输入内容并添加
2. **添加推理时**：在笔记的"推理"栏输入内容并添加
3. **添加待办时**：在笔记的"待验证"栏输入内容并添加

#### 检测逻辑
- 玩家输入的文本与关键词或别名进行匹配
- 匹配方式：包含匹配（文本中包含关键词即触发）
- 不区分大小写
- 每个关键词只触发一次

### 3.2 解锁反馈

#### 解锁类型
1. **dialog（对话解锁）**：弹出对话框，显示隐藏推理内容
2. **clue（线索解锁）**：自动添加一条线索到笔记
3. **confidence（信心值）**：直接增加信心值

#### 视觉反馈
- Toast提示："发现关键词：XXX！"
- 播放成功音效
- 信心值增加动画
- 笔记UI中关键词标记为已解锁

### 3.3 笔记UI集成

#### 已解锁关键词展示
- 在笔记弹窗底部添加"已解锁关键词"区域
- 显示已解锁的关键词列表（关键词 + 描述）
- 未解锁的关键词显示为"???"（不剧透）

#### 输入提示
- 当玩家输入接近关键词时，给出 subtle 提示（可选，避免剧透）
- 或者完全不提示，让玩家自己探索

## 六、风险和注意事项

### 风险1：关键词检测过于简单
- **问题**：玩家可能无意中输入关键词，缺少探索感
- **解决**：关键词设计要合理，需要玩家真正思考才能想到

### 风险2：剧透问题
- **问题**：显示未解锁的关键词可能剧透
- **解决**：未解锁的关键词显示为"???"，只显示数量

### 风险3：重复触发
- **问题**：玩家多次输入同一关键词
- **解决**：每个关键词只触发一次，记录在discoveredKeywords中

### 注意事项
- 关键词匹配不区分大小写
- 支持别名匹配
- 解锁内容要符合案件剧情
- 信心值奖励要平衡（不要太高）
