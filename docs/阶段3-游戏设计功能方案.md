# 阶段3：游戏设计功能 - 详细可执行方案

## 一、目标与范围

### 目标
基于阶段2.5准备的游戏化数据（12个游戏案例、10个改编建议、10种诡计映射、5个游戏模板），在网站上开发游戏设计相关的功能页面，使网站从"案例资料库"升级为"推理游戏设计参考工具"。

### 核心价值
- **游戏设计师**：可以快速查找适合特定诡计类型的游戏机制和模板
- **小说/剧本创作者**：可以查看案例的游戏化改编方向，获取交互设计灵感
- **玩家/爱好者**：可以了解推理游戏的设计原理和经典案例对比

### 范围
- 新增3个页面：游戏设计总览页、游戏模板详情页、诡计机制映射页
- 增强1个页面：案例详情页（添加游戏化改编建议展示）
- 新增1个组件：游戏案例对比卡片
- 不做：完整的游戏引擎、可玩的游戏原型、用户登录系统

### 不在范围
- 不做可交互的游戏原型（阶段4再考虑）
- 不做用户账号和收藏功能
- 不做后端API（保持静态站点）

## 二、页面设计与功能规格

### 页面1：游戏设计总览页（/game-design）

#### 2.1.1 页面定位
游戏设计功能的入口页，展示游戏模板库和诡计映射表的总览，引导用户深入查看。

#### 2.1.2 页面结构
```
┌─────────────────────────────────────────┐
│  Hero区域                                │
│  标题：推理游戏设计参考库                 │
│  副标题：从经典案例到可复用的游戏机制      │
│  统计：5个模板 | 10种诡计 | 12个游戏案例  │
├─────────────────────────────────────────┤
│  游戏模板库（卡片网格，5个）              │
│  每个卡片：模板名、核心循环、适配诡计、    │
│  参考案例数、查看详情按钮                 │
├─────────────────────────────────────────┤
│  诡计类型→游戏机制映射（标签云/列表）     │
│  10种诡计类型，每种显示：                 │
│  诡计名、适配游戏类型、核心机制数量、      │
│  参考案例数                              │
│  点击跳转到诡计详情页                     │
├─────────────────────────────────────────┤
│  游戏案例精选（横向滚动，6-8个）          │
│  展示12个游戏案例的卡片，点击跳转详情      │
├─────────────────────────────────────────┤
│  使用指南                                │
│  3步：选择诡计类型 → 查看适配机制 → 套用模板 │
└─────────────────────────────────────────┘
```

#### 2.1.3 数据来源
- `getGameTemplates()` - 游戏模板库
- `getTrickMechanismMap()` - 诡计映射表
- `getGameCases()` - 游戏案例列表

#### 2.1.4 交互设计
- 模板卡片：hover效果，点击跳转模板详情页
- 诡计标签：点击跳转到诡计映射页对应锚点
- 游戏案例卡片：点击跳转到案例详情页
- 响应式：移动端单列，平板双列，桌面三列

├─────────────────────────────────────────┤
│  阶段设计（默认Tab）                      │
│  4个阶段，每个阶段显示：                   │
│  - 阶段名称                               │
│  - 玩家目标                               │

│  - 设计要点（如果有）                     │
│  时间线/流程图可视化                       │
├─────────────────────────────────────────┤
│  适配诡计Tab                              │
│  列出该模板适配的诡计类型，每种显示：       │
│  - 诡计名 + 描述                          │
│  - 为什么适配这个模板                      │
│  - 参考案例链接                           │
├─────────────────────────────────────────┤
│  参考案例Tab                              │
│  列出使用该模板的游戏案例，卡片展示         │
│  每个卡片：案例名、玩法类型、核心机制、     │
│  查看详情按钮                             │
├─────────────────────────────────────────┤
│  设计要点Tab                              │
│  难度曲线、适合时长、通用设计建议           │
├─────────────────────────────────────────┤
│  上一个/下一个模板导航                     │

#### 2.2.3 数据来源
- `getGameTemplates()` - 获取指定模板的详细数据
- `getGameCases()` - 获取使用该模板的游戏案例
- `getTrickMechanismMap()` - 获取适配诡计的详细信息

- Tab切换：无刷新，URL hash记录当前Tab（支持深链）

- 参考案例卡片：点击跳转案例详情页
- 适配诡计：点击跳转到诡计映射页

### 页面3：诡计机制映射页（/game-design/tricks）

#### 2.3.1 页面定位
展示10种诡计类型对应的游戏机制、关卡设计要点和参考案例，是游戏设计师查找"某种诡计该怎么做成游戏"的核心页面。

#### 2.3.2 页面结构
```
┌─────────────────────────────────────────┐
│  面包屑：游戏设计 > 诡计机制映射           │
├─────────────────────────────────────────┤
│  页面标题 + 搜索/筛选栏                   │
│  搜索框：按诡计名/机制名搜索               │
│  筛选：按适配游戏类型筛选                  │
├─────────────────────────────────────────┤
│  诡计列表（10种，每种一个区块）            │
│  ┌───────────────────────────────────┐  │
│  │ 诡计名 + 描述（锚点ID）            │  │
│  │ 适配游戏类型：标签                 │  │
│  │ 核心机制：3-5个标签                │  │
│  │ 关卡设计要点：4条（可折叠）         │  │
│  │ 参考案例：3-5个，链接到案例详情     │  │
│  │ [查看使用该诡计的模板] 按钮         │  │
│  └───────────────────────────────────┘  │
├─────────────────────────────────────────┤
│  侧边导航（桌面端）：10种诡计的快速跳转    │
└─────────────────────────────────────────┘
```

#### 2.3.3 数据来源
- `getTrickMechanismMap()` - 诡计映射表完整数据
- `loadAllCases()` - 根据诡计类型筛选参考案例

#### 2.3.4 交互设计
- 搜索：实时过滤诡计列表（客户端JS）
- 筛选：按游戏类型筛选，多选用checkbox
- 侧边导航：点击平滑滚动到对应诡计区块
- 参考案例：点击跳转案例详情页
- "查看使用该诡计的模板"：跳转到模板详情页（如果有适配）

## 四、技术实现细节

### 4.1 数据加载
- 使用现有的 `caseLoader.ts` 中的函数：
  - `getGameTemplates()` - 加载游戏模板库
  - `getTrickMechanismMap()` - 加载诡计映射表
  - `getGameCases()` - 获取所有游戏案例
  - `loadAllCases()` - 获取所有案例（用于参考案例筛选）
- 静态构建时加载，客户端不额外请求

### 4.2 动态路由
- 模板详情页使用 `getStaticPaths()` 生成静态页面
- 模板名称作为URL参数，需要处理中文编码

### 4.3 Tab切换实现
- 使用URL hash（如 `#阶段设计`）记录当前Tab
- 页面加载时读取hash，切换到对应Tab
- 点击Tab时更新hash，无刷新切换

### 4.4 搜索和筛选
- 诡计映射页的搜索和筛选用客户端JS实现
- 所有数据在页面加载时已存在，纯前端过滤

### 4.5 组件复用
- 复用现有组件：Layout、Header、Footer、CaseCard、Tag等
- 新增组件：TemplateCard、TrickSection、TimelineFlow（核心循环可视化）

### 4.6 样式方案
- 使用 Tailwind CSS（项目已配置）
- 保持与现有页面一致的设计语言
- 新增样式写在组件的 `<style>` 标签中，不污染全局
