# Fun Detective 首页与分页 UI/UX 审核报告

**审核日期**：2026-09-08  
**审核范围**：线上首页、来源分类页、游戏设计页、关于页，以及首页搜索/加载更多交互的源码核对。  
**线上地址**：<https://waterslin-ann.github.io/fun_detective/>  
**本轮范围说明**：暂缓可玩游戏的玩法检查，本报告只关注站点首页和内容分页。

## 结论摘要

站点主导航、首页检索和基础内容路由可以使用，首页模糊搜索已在线验证：输入“东方快车”后结果收敛为 1 条，且结果计数同步为“共 1 条”。目前主要风险集中在内容呈现与可访问性，而不是路由本身：卡片没有实际图片资源、搜索框缺少可访问名称、首页首屏视觉层级偏空、分类页缺少继续筛选能力、部分中文内容混入英文残片，另外“关于”页技术栈说明已经落后于仓库实际版本。

## P1/P2 问题清单

| 编号 | 优先级 | 页面 | 问题 | 证据/影响 | 优化建议 |
|---|---|---|---|---|---|
| P1-01 | P1 | 首页、分类页 | 案件卡片没有实际图片资源 | 线上 DOM 的 `document.images` 数量为 0；卡片视觉上只有文字和留白。用户无法通过封面、场景或来源快速扫描，内容库的辨识度和点击动机偏弱。 | 若暂时没有授权图片，使用统一的来源/地区视觉封面或 CSS 图形占位，并给出明确的 `alt`；有可靠素材后再逐步替换，避免装饰性空白图片区。 |
| P1-02 | P1 | 首页 | 搜索输入缺少可访问名称 | `#search-input` 没有 `aria-label`、`aria-labelledby` 或显式 `<label>`，AX 树只暴露为 `text field (settable) search-input`。屏幕阅读器用户只能得到技术 ID。 | 增加可见 `<label for="search-input">搜索案件</label>`，或至少增加 `aria-label="搜索案件名称、简介或诡计"`；保留 placeholder 作为示例，不把 placeholder 当唯一标签。 |
| P1-03 | P1 | 首页 | Hero 右侧首屏留白过大，缺少产品/内容视觉锚点 | 桌面首屏 Hero 内容只占左侧约 3/5，右侧为空；站点的核心资产是案件库，但首屏没有案例封面、数据可视化或入口卡片。 | 在不增加营销式大图的前提下，增加一个可扫描的“今日案例/随机案例”预览或轻量统计可视化；限制 Hero 内容宽度并优化左右构图，让首屏直接展示内容资产。 |
| P2-01 | P2 | 首页 | 搜索、筛选和排序状态不进入 URL | 当前交互由客户端状态驱动，刷新或复制链接后会回到默认列表，无法分享一个已筛选的案例集合，也不利于浏览器后退恢复。 | 将 `q/source/continent/region/sort/page` 同步到 query string；初始化时从 URL 恢复，筛选变化使用 `history.replaceState`。 |
| P2-02 | P2 | 首页 | “加载更多”是客户端分页，但缺少加载中的反馈和键盘焦点策略 | 源码在点击后直接增加 `currentPage` 并重排 DOM；数据量变大时用户看不到处理中状态，新增内容也没有明确的焦点落点。 | 点击后临时禁用按钮并显示“正在加载”；完成后把焦点移到第一条新增卡片或按钮，并用 `aria-live` 宣布显示数量变化。 |
| P2-03 | P2 | 首页 | 地区二级菜单的键盘/语义支持不足 | 地区项使用 `div`，PC 依赖 hover，移动端依赖点击 class；没有 `role="menu"/menuitem`、`aria-expanded` 或 Escape 关闭契约。 | 优先改为按钮/列表语义；触发器增加 `aria-expanded` 和 `aria-controls`；支持 Tab、Enter、方向键和 Escape；移动端保持可见的当前选择。 |
| P2-04 | P2 | 来源分类页 | 分类页只有长列表，没有页内搜索、筛选或分页 | 推理小说 83 条、真实案件 47 条、游戏 39 条；分类页直接连续展示大量卡片，用户从分类进入后仍需回首页才能筛选。 | 复用首页的搜索/排序/地区筛选组件，或至少提供分类内搜索和分页；在列表顶部固定显示结果数与当前筛选条件。 |
| P2-05 | P2 | 全站内容 | 部分中文简介混入英文残片 | 在线看到“allegedly”“aspiring actress”“crew”等原文残片，数据文件中也能确认这些字段。会破坏中文阅读连续性，并降低真实案件内容的可信度。 | 建立发布前文本质量检查：中英文混排白名单、未翻译词扫描、专名统一；保留专有名词时使用中文解释或括号补充。 |
| P2-06 | P2 | 游戏设计页 | 统计/文案有潜在漂移 | 页面统计为 5 个模板、10 类诡计、39 个游戏案例，但“经典游戏案例”副文案固定写“12个推理游戏案例”，实际精选区只展示前 6 个。 | 文案改为动态值，例如“共 {gameCases.length} 个案例，精选展示 {featuredGames.length} 个”；避免后续数据增长后继续产生冲突。 |
| P2-07 | P2 | 关于页 | 技术栈版本说明过时 | 页面写“Astro 4.x”，仓库 `package.json` 当前为 `astro ^7.2.10`。公开页面会向协作者/读者传递错误的维护信息。 | 改成当前主版本，或写成不易过时的“基于 Astro + TypeScript”；发布前将 About 页版本信息纳入构建检查。 |
| P2-08 | P2 | 首页/全站 | 案件卡片只有标题链接，不是整卡可点击 | `CaseCard.astro` 只给标题包裹 `<a>`，卡片正文和标签点击不会进入详情；在卡片密集布局中，点击热区小于用户直觉。 | 保留标题链接的语义，同时让整卡支持点击（使用卡片级链接或 JS 键盘代理），避免嵌套链接；补充 hover/focus-visible 状态。 |
| P2-09 | P2 | 首页/关于页 | 统计指标没有解释口径 | “覆盖大洲”“国家/地区”“平均难度”有数字但无口径说明，尤其平均难度的小数精度和缺失值处理对普通用户不可见。 | 在指标旁增加短 tooltip/说明链接，明确统计更新时间、难度范围和去重规则；数据更新时同步展示更新时间。 |

## 已验证正常项

1. 主导航可以到达首页、推理小说、真实案件、游戏案例、游戏设计和关于页。
2. 首页模糊搜索“东方快车”可以得到“东方快车谋杀案”单条结果，结果计数同步为 1。
3. 首页源类型与排序控件存在，首页初始结果显示为 12 条并提供“加载更多”入口。
4. 游戏设计页提供可玩原型、关卡生成器、模板库和诡计映射入口。
5. 关于页的项目目标、数据来源、部署方式和数据声明结构完整。

## 建议的优化顺序

### 第一批：先修可访问性和内容可信度

- 给搜索框和地区菜单补齐语义、键盘操作、焦点与 Escape 关闭。
- 清理英文残片，补发布前数据质量检查。
- 更新关于页技术栈版本，并把游戏设计页的案例数量改为动态文案。

### 第二批：改善首页内容扫描

- 为卡片提供统一视觉封面/占位，并补充 alt 文本。
- 缩小 Hero 的空白区域，增加一个真实案例预览或“随机案例”入口。
- 将整卡点击热区、hover 和 focus-visible 状态统一。

### 第三批：提升可复用性

- 将筛选状态同步 URL，支持复制链接、后退恢复和分享。
- 分类页复用首页筛选组件，避免“进入分类后还要回首页筛选”。
- 为加载更多增加状态反馈、`aria-live` 和新增内容焦点管理。

## 建议验收用例

- 键盘 Tab 从导航到搜索、类型、地区、排序、加载更多，全程焦点可见且顺序合理。
- 屏幕阅读器能读出搜索框用途、地区菜单展开状态和结果数量变化。
- 输入不存在的关键词、清空关键词、连续切换类型/地区/排序后，结果数、按钮状态和 URL 保持一致。
- 点击加载更多后，新增 12 条、按钮文本、滚动位置和焦点均符合预期。
- 375px、414px、768px、1280px 宽度下，Hero、筛选栏、地区菜单、卡片网格无横向溢出。
- 随机抽查推理小说、真实案件、游戏三类各 10 条，中文文案无未处理英文残片，卡片封面和 alt 正常。
- 游戏设计页的统计数字、精选数量和“查看全部”目标一致；关于页技术栈与 `package.json` 一致。

## 审核边界

本轮没有修改代码，也没有继续验证东方快车原型的审判流程、证据逻辑或遮罩交互；这些内容保留到后续游戏功能专项回归。
