# 东方快车：可玩性、逻辑性与趣味性测试方案及优化报告

**审查日期**：2026-09-07  
**范围**：公开版 `play/?case=orient-express`、当前源码、既有自动化脚本  
**评审视角**：首次玩家、重复玩家、键盘/移动端玩家，以及关卡与叙事设计

## 结论先行

公开版已经补上加载态、开场进度、跳过开场、场景热点、存档选择和渐进式工具栏，UI 基线较上一轮明显提高。但东方快车目前还不是一个稳定的“推理审判”闭环：存档恢复可将玩家卡死；关卡的通关和评级主要由收集/点击数量与初始信心值决定；若干核心线索在数据层互相冲突。它更像带推理题材包装的交互式导览，而非需要玩家建立、检验、修正假设的案件。

最优先的工作不是继续加功能，而是先让“存档恢复、推理门槛、结局判定、线索一致性”成为可测试的产品契约。

|---|---|---|---|---|---|
| OE-P0-01 | P0 | 可玩性 | **存档恢复进入无限选择循环。** `continueSavedGame()` 重新赋值内部 `state`，而渲染始终读取导出的旧 `GameState.state`；点击“继续游戏”后仍判断 `pendingSaveChoice=true`。 | 有存档的回访玩家无法进入游戏，等同主路径不可用。 | 不再替换 state 对象，改为 `Object.assign(state, saved)`；或所有读取改为 `GameState.getState()`。加入“预置调查期存档→继续→进入调查场景”的端到端测试。 |
| OE-P0-02 | P0 | 测试 | 现有构建、schema、smoke 均未覆盖存档恢复，生产阻断未被拦截。 | 测试绿灯不能代表玩家主路径可用。 | 为每案加入 fresh/save/resume/reset 四态测试；保存 `gamePhase`、场景、证据、证人、关联数后逐项断言恢复。 |

| OE-P1-01 | P1 | 推理逻辑 | **“手帕”同时被设计为赫伯德夫人和公主两条“正确”关联、两条“正确”矛盾。** 两条 link 均可加分，两个证人也都可被同一手帕质询成功。 | 证据归属的互斥性被破坏，玩家学到的是穷举，不是排除法。 | 将其改为显式的竞争假设：`H` 初看指向赫伯德，俄文字形/额外证据排除后才指向公主。一次只能成立一个最终归属；错误假设应留下可修正的笔记，而非同时奖励。 |

| OE-P1-03 | P1 | 关卡结构 | 调查目标要求“发现证词矛盾”，但矛盾只能在审判阶段通过“异议→选证据”触发；进入餐车却不要求任何矛盾。 | 目标与可执行动作的 phase 冲突，玩家会被要求完成当前阶段无法完成的事情。 | 将该目标移到 `trial`；调查阶段改为“建立一条可审判的假设”。进入审判至少要求一个已验证的“证据-人物/时间”推断。 |
| OE-P1-04 | P1 | 可玩性 | 审判的完成门槛是“质询所有证人”；`进入总结陈词` 不要求发现矛盾或正确出示证据。 | 玩家可跳过推理，只遍历证人仍推进结局。 | 总结门槛改为：至少识别 N 条关键矛盾，且每条对应不同推理节点；没有足够证据时显示“还缺哪一条论证链”。 |
| OE-P1-05 | P1 | 趣味性 | 信心从 100 起算；正确关联/异议只会加分到上限，错误才扣分。玩家不犯错、不建立关键链也可能得到 S 级。 | “完美推理”与实际推理质量脱钩，重玩缺少目标。 | 以“核心链完成度 + 可选链完成度 + 错误惩罚”计算评级。示例：核心三链缺一则最高 B；S 需要完整因果链与少量无效指控。 |
| OE-P1-06 | P1 | 趣味性 | 最终选择被标为“会决定结局”，但新 `EndingUI` 实际只按信心值选评级，未读取 `final-choice` 渲染不同叙事。 | 道德抉择是伪分支，玩家选择没有叙事后果。 | 结局数据按 `grade × finalChoice` 配置，至少提供“交警方 / 维持第二解答”两段不同后日谈和成就；文案与实现只保留真实有效的承诺。 |
| OE-P1-07 | P1 | 推理体验 | 关联板对正确预设链接直接揭示结论并加分；错误组合的学习反馈与推断成本不足。 | 玩家可通过两两试点取代阅读、记录和比较。 | 将关联拆为“提出假设→选择依据→系统反证/支持”。只对有证据依据的组合开放高价值结论；错误组合给可解释的反证，不宜一律扣分。 |
| OE-P1-08 | P1 | 结局交互 | **结局页“再玩一次”调用不存在的 `GameState.reset()`。** `GameState` 只导出 `resetSavedGame()`，未导出 `reset()`；按钮会先隐藏结局再抛出运行时错误。 | 通关后最重要的复玩入口失效，玩家只能重载或离开案件，重玩设计无法成立。 | 复玩逻辑调用已存在且语义完整的重置 API，或提供专用 `restartCase()`；先在测试中断言点击后无 page error、进入初始开场、旧进度已清除。 |

| OE-P1-10 | P1 | 键盘/触控可达性 | 对话框、笔记、时间线和证据板虽然部分带 `role=dialog`，却没有焦点陷阱或稳定的焦点返回；多个关闭叉没有 `aria-label`，并以约 32px 宽高呈现。笔记删除操作还仅在 `group-hover` 时可见。 | 键盘用户可 Tab 到遮罩后的页面；触屏用户难以发现或准确点击删除/关闭，辅助技术也不能可靠说明操作含义。 | 所有 modal 打开时聚焦第一个可操作元素、Tab 循环于 modal 内、关闭时回到触发按钮；关闭/删除使用带文本替代的 44×44px 目标，不能仅依赖 hover 显示。 |
| OE-P2-04 | P2 | 即时反馈 | 时间线的“检测矛盾”在尚未发现足够事件时返回 `0`，调用方直接重渲染且不提供任何反馈；按钮仍呈现为可执行主操作。 | 玩家不知道是没有矛盾、线索不足还是点击失败，容易反复点击或误判系统故障。 | 无可检测矛盾时禁用并给出“还需发现 X/Y”提示；检测成功后在结果区高亮新增矛盾，并在测试中覆盖两种状态。 |
| OE-P2-01 | P2 | 视觉/移动端 | 约 581px 宽度下，右侧场景出口覆盖赫伯德夫人标签；顶栏案件名过早截断。 | 关键信息相互遮挡，移动端空间感和可读性下降。 | 出口移至场景底部导航条或只显示当前可行动出口；热点标签使用碰撞规避/随屏幕重排；标题允许两行或将阶段与标题分层。 |
| OE-P2-02 | P2 | 视觉/沉浸 | 列车走廊主要由渐变、线框矩形和火柴人构成，缺少车厢、雪夜、乘客关系的题材细节。 | “东方快车”作为第一屏信号不够强，推理氛围和探索欲偏弱。 | 用低成本但具象的车厢平面/剪影场景替代通用渐变；将可调查物嵌入车门、床铺、窗、餐桌等真实空间锚点。动效只用于发现线索和推理成立。 |
| OE-P2-03 | P2 | 可访问性 | 一部分系统状态仍靠颜色、emoji 与微小标签表达；缩小后的文字接近 11px。 | 触控、低视力和键盘用户的可读性仍有风险。 | 保持 44px 主触控区、正文最小 16px；状态使用图标+文字；完成 375/768/1024/1440 截图及 Tab/Esc 回归。 |

## 建议的推理主循环

```text
观察场景
  -> 收集“事实卡”（不含结论）
  -> 形成多个假设
  -> 用证词 / 时间线 / 物证验证或排除
  -> 得到可审判的论证链
  -> 在审判中针对具体陈述出示证据
  -> 根据论证链完整度与最终抉择生成结局
```

东方快车的最小核心链建议固定为三条：

1. **逃走路线是假象**：窗户 + 雪地无脚印 -> 排除外人从窗户离开。
2. **死亡时间被伪造**：怀表 + 列车员前后证词 -> 怀表不能直接代表死亡时间。
3. **复仇网络成立**：至少三名乘客与阿姆斯特朗案的独立关系 -> “单一凶手”假设失效。

手帕应是“竞争假设”的教学节点，而非双重正确答案：先让玩家得到 H 的歧义，再用俄文字形或人物背景来收束结论。

## 交互遮罩与可恢复性复验（2026-09-07）

本轮将“能看到控件”与“玩家能稳定回到可操作状态”分开检查。审计覆盖审判异议、关联板结果、对话、证据详情、笔记、时间线、教程、通用确认框和结局。

| 检查项 | 已核实结果 | 发布门槛 |
|---|---|---|
| 异议动画结束 | 失败：状态回落后 DOM 未隐藏（OE-P0-03）。 | 1500ms 后全屏遮罩不可见，且可见证据栏可被点击/Tab 到。 |
| 关联结果与板面刷新 | 失败：内容字段未渲染，延迟重开板面可盖住结果框（OE-P0-04）。 | 结果正文可见；确认前不重开板面；关闭后才以同一状态刷新。 |
| 结局复玩 | 失败：调用未定义 API（OE-P1-08）。 | 点击“再玩一次”没有 `pageerror`，回到开场且无旧存档/旧浮层。 |
| 可取消浮层 | 不一致：对话只允许关闭按钮/Esc；时间线、笔记、证据详情可用不同方式关闭；结局和异议未纳入统一 Esc 处理（OE-P1-09）。 | 每个可取消浮层都有可见关闭路径、Esc 路径和明确遮罩点击策略；不可取消的终局只保留明确的可达出口。 |
| 焦点和触控 | 不足：通用辅助函数未被大多数浮层实际采用，若干图标按钮低于 44px 且无名称（OE-P1-10）。 | 打开、Tab 循环、Esc/关闭后的焦点返回均自动化验证；关键按钮命中区至少 44×44px。 |
| 无结果操作 | 不足：时间线“检测矛盾”无可检测项时无反馈（OE-P2-04）。 | 不能产生结果的主操作必须禁用或解释前置条件。 |

## 分层测试方案

### 1. 数据与叙事一致性：每次提交必跑

| 用例 | 断言 |
|---|---|
| 证据可追溯 | 每个 timeline 事件关联可见的证词/物证及原文摘录。 |
| 关系互斥 | 同一证据不能同时产生两个“最终正确”的互斥归属，除非显式标记为并存关系。 |
| 目标可达 | 目标 phase 内必须存在完成动作；`investigation` 目标不能只在 `trial` 完成。 |
| 推进有效 | 进入审判、进入总结、S 级结局分别要求明确的核心论证链。 |
| 分支真实 | 每个可见的最终选项均有不同的结局数据或成就后果。 |

建议扩展 `scripts/validate-case-data.cjs`，把上述前四项作为错误，分支无效作为警告转错误的发布门禁。

### 2. 状态机测试：每案必跑

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| ST-01 | 无存档 | 冷启动 | loading 后进入开场，显示进度与跳过。 |
| ST-02 | 调查中存档 | 重载 -> 继续游戏 | 只出现一次选择框，恢复到原场景、证据数、证人数、关联与目标。 |
| ST-03 | 调查中存档 | 重载 -> 重新开始 | 清除该案件存档，进入开场，不影响其他案件。 |
| ST-04 | 未达条件 | 前往餐车 | 明确列出缺证据/证人/论证链，并有返回调查的行动。 |
| ST-05 | 达审判条件 | 前往餐车 -> 确认 | 进入审判，调查状态不可被误覆盖。 |
| ST-06 | 审判中 | 错误出示、正确出示 | 反馈、信心、证词状态和可继续性一致。 |
| ST-07 | 结局 | 两个最终选择 | 产生不同叙事/成就，统计与评级正确。 |

### 3. 浏览器端到端测试：CI 必跑

使用 Puppeteer 或 Playwright，保留现有脚本但新增独立 `e2e-game-flow`：

- 每个用例使用新的 browser context，避免本地存档串扰。
- 375、768、1024、1440 四个视口断言无横向滚动、无遮挡的主操作、主触控区至少 44px。
- 覆盖 `ST-01` 至 `ST-07`，并保存失败截图、console log 与 localStorage 快照。
- 键盘路径：Tab 到案件操作、Enter 激活、Esc 关闭更多/笔记/证据详情、关联板可用 Space 选择。
- 视觉回归不能只截图“调查页”；至少覆盖 loading、存档选择、调查、关联板、审判、结局。

### 4. 人工可玩性测试：每次关卡改动后

招募 5 名未接触过项目的玩家，分两组记录：

| 指标 | 目标 | 判定方式 |
|---|---:|---|
| 首次有效推断时间 | <= 5 分钟 | 首次说出“证据 A 支持/反驳人物 B”的时间。 |
| 非提示完成第一核心链 | >= 80% | 观察/证词/关联三步均由玩家主动完成。 |
| 盲点率 | <= 20% | 不读信息而遍历所有组合的玩家比例。 |
| 阶段迷失率 | <= 10% | 玩家无法说出当前目标或下一步。 |
| 主观趣味评分 | >= 4/5 | 结束后问“推理是我做出来的，而不是系统告诉我的”。 |

记录屏幕、行动序列和玩家口述。不要只问“好不好玩”；重点问“你为什么认为这条线索重要”“刚才哪一步是你自己的判断”。

## 实施顺序

1. 修复 **OE-P0-01**，并先补 ST-02/03，阻止存档循环再次上线。
2. 处理 **OE-P1-01 至 OE-P1-06**：先统一事实数据，再把推进、评级和结局绑定到论证链。
3. 为关联板加入竞争假设与可解释反馈，削弱穷举收益。
4. 最后处理场景资产、移动避让与视觉回归，使东方快车从“通用网页游戏”变成可辨识的雪夜列车案件。

## 评审依据

- `ui-ux-pro-max`：多步进度、可跳过引导、44px 触控目标、键盘全路径、375/768/1024/1440 响应式验证。
- `frontend-design`：视觉资产、文字和结构要服务“被雪困住的列车、封闭空间、12 人复仇网络”，不能由通用渐变和装饰性状态替代。
- 本报告不建议扩展更多案件或更多成就，直到东方快车的核心推理闭环能被上述状态机与玩家测试稳定验证。
