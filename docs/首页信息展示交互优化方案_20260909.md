# 首页信息展示交互优化方案

> 日期：2026-09-09
> 范围：线上首页（202案件资料库）信息展示与交互优化
> 定位调整：从「游戏案件库」转向「推理案件结构化参考库」，核心引导延伸阅读（书籍/影视/资料），线上屏蔽游戏入口，本地保留

---

## 一、背景与目标

### 1.1 当前问题

基于线上首页截图（waterslin-ann.github.io/fun_detective/）与代码审查，发现以下问题：

| 问题 | 现状 | 影响 |
|---|---|---|
| Hero 区域过高 | `py-16`（64px上下），大标题+5统计+右侧速览卡片 | 首屏几乎看不到案件卡片，用户需要滚动才能看到内容 |
| 卡片封面占比过大 | 封面 `120px` 高，72px大图标占独立空间 | 单卡高度~340px，一屏仅展示2-3行，信息密度低 |
| 移动端卡片过高 | 纵向布局，封面+内容堆叠 | 移动端一屏仅1张卡片，浏览效率极低 |
| 分页交互低效 | 每页12条，「加载更多」按钮 | 202条需要点击17次，滚动体验不连贯 |
| 定位偏游戏 | 文案强调「游戏设计」，导航有「游戏设计」入口 | 与当前「参考资料库」定位不符 |
| 缺少延伸阅读引导 | 卡片无参考链接/视频入口 | 用户无法快速判断「这个案件值不值得深入」 |

### 1.2 优化目标

1. **首屏效率**：首屏至少展示第一行案件卡片（3张）
2. **信息密度**：桌面端单卡高度降低30%+，移动端降低50%+
3. **浏览流畅度**：无限滚动自动加载，每页50条
4. **定位清晰**：强调「案件参考库」，引导延伸阅读
5. **环境隔离**：线上屏蔽游戏入口，本地保留测试能力

## 二、游戏入口屏蔽方案

### 2.1 屏蔽范围

| 入口 | 位置 | 线上处理 | 本地处理 |
|---|---|---|---|
| 导航栏「游戏设计」 | BaseLayout header nav | 隐藏 | 保留 |
| 底部「游戏设计」链接 | BaseLayout footer | 隐藏 | 保留 |
| 案件选择页 | `/game-design/prototype/` | 显示「内部测试中」遮罩 | 正常访问 |
| 游戏游玩页 | `/game-design/prototype/play` | 显示「内部测试中」遮罩 | 正常访问 |

### 2.2 实现方式

**环境判断**：使用 Astro 的 `import.meta.env.DEV`
- 构建时（`astro build`）：`import.meta.env.DEV === false` → 线上环境
- 开发时（`astro dev`）：`import.meta.env.DEV === true` → 本地环境

**BaseLayout 修改**：
```astro
---
const isDev = import.meta.env.DEV;
---
<!-- 导航栏 -->
{isDev && (
  <a href="/fun_detective/game-design" class="...">游戏设计</a>
)}
```

**prototype 页面遮罩**：
- 在 `index.astro` 和 `play.astro` 顶部添加环境判断
- 非 DEV 环境渲染全屏遮罩，提示「内部测试中，本地环境可体验」
- 遮罩不删除页面内容，仅覆盖，后续恢复只需移除遮罩代码

## 三、Hero 区域优化

### 3.1 文案调整

| 元素 | 当前 | 改为 |
|---|---|---|
| 主标题 | 探索全球**案件**的奥秘 | 探索全球**经典案件**的诡计与叙事 |
| 副标题 | 汇集推理小说、真实案件、影视游戏中的经典案例，为小说创作和游戏设计提供结构化的灵感与参考。 | 汇集推理小说、真实案件、影视游戏中的经典案例，为推理爱好者和创作者提供结构化的案件参考与延伸阅读指引。 |

- 1080p 屏幕首屏可展示 Hero + 搜索栏 + 第一行案件卡片（3张）

## 四、案件卡片优化

### 4.1 封面区压缩

| 属性 | 当前 | 改为 | 说明 |
|---|---|---|---|
| 封面高度 | `120px` | `72px` | 减少40% |
| 图标尺寸 | `72px × 72px` | `40px × 40px` | 作为背景水印 |
| 图标位置 | `right: 8px; bottom: 6px` | `right: 12px; top: 50%; transform: translateY(-50%)` | 垂直居中 |
| 图标透明度 | `rgba(255,255,255,0.16)` | `rgba(255,255,255,0.12)` | 更淡，不抢信息 |
| 封面 padding | `12px 14px` | `10px 12px` | 紧凑 |
| 类型标签 | `font-size: 12px; padding: 2px 10px` | `font-size: 11px; padding: 1px 8px` | 缩小 |
| 地区文字 | `font-size: 11px` | `font-size: 10px` | 缩小 |

### 4.2 内容区压缩

| 属性 | 当前 | 改为 | 说明 |
|---|---|---|---|
| 内容 padding | `p-5`（20px） | `p-4`（16px） | 减少20% |
| 难度/类型标签间距 | `mb-3` | `mb-2` | 紧凑 |
| 标题字号 | `text-lg` | `text-base font-bold` | 略缩 |
| 标题行数 | `line-clamp-2` | `line-clamp-2` | 保持2行 |
| 简介字号 | `text-sm` | `text-sm` | 保持 |
| 简介行数 | `line-clamp-3` | `line-clamp-2` | 减少1行 |
| 诡计标签数量 | `slice(0, 3)` | `slice(0, 2)` | 减少1个 |
| 诡计标签间距 | `gap-1.5 mb-3` | `gap-1 mb-2` | 紧凑 |
| 底部元信息 | `pt-3 border-t` | `pt-2 border-t` | 紧凑 |

### 4.3 新增「延伸阅读」引导

在卡片底部元信息行上方，新增延伸阅读提示：

```
📖 2篇资料 · 🎬 1个视频
```

- 数据来源：`基本信息.参考链接`（数量）+ `基本信息.推荐视频`（数量）
- 仅在有数据时显示，无数据时隐藏
- 样式：`text-xs text-stone-500`，图标用 inline SVG
- 点击卡片进入详情页可查看具体链接

### 4.4 移动端横向布局

**断点**：`max-width: 768px`

**布局变化**：
- 卡片从 `flex flex-col` 改为 `flex flex-row`
- 封面区：`width: 40%`，高度自适应（与内容区等高）
- 内容区：`width: 60%`，`p-3`
- 简介：`line-clamp-2` → `line-clamp-2`（保持）
- 诡计标签：`slice(0, 2)` → `slice(0, 1)`（只显示1个）

**预期效果**：
- 移动端单卡高度从 ~340px 降至 ~160px
- 一屏可展示 3-4 张卡片（原仅1张）

## 五、瀑布流 + 无限滚动

### 5.1 布局方案

**从 CSS Grid 改为 CSS Columns 瀑布流**：

```css
#case-grid {
  column-count: 1;
  column-gap: 16px;
}
@media (min-width: 768px) {
  #case-grid {
    column-count: 2;
  }
}
@media (min-width: 1024px) {
  #case-grid {
    column-count: 3;
  }
}
#case-grid > article {
  break-inside: avoid;
  margin-bottom: 16px;
}
```

**优势**：
- 卡片高度自然错落，充分利用垂直空间
- 无需 JS 计算位置，纯 CSS 实现
- 响应式列数自动调整

### 5.2 无限滚动

**实现方式**：`IntersectionObserver`

```typescript
// 在 case-browser.ts 中新增
const sentinel = document.createElement('div');
sentinel.id = 'scroll-sentinel';
caseGrid.parentElement.appendChild(sentinel);

const observer = new IntersectionObserver((entries) => {
  if (entries[0].isIntersecting && browser.hasMore && !browser.loading) {
    browser.loadNextPage();
  }
}, { rootMargin: '200px' });

observer.observe(sentinel);
```

**逻辑**：
- 页面底部放置一个「哨兵元素」（sentinel）
- 当哨兵进入视口（提前200px触发），自动加载下一页
- 加载中显示骨架屏（3-5个占位卡片）
- 全部加载完成后，哨兵替换为「已加载全部 202 件案件」

### 5.3 分页参数

| 参数 | 当前 | 改为 |
|---|---|---|
| 每页数量 | 12 | 50 |
| 加载方式 | 点击「加载更多」按钮 | 滚动自动加载 |
| 降级方案 | 无 | 保留「加载更多」按钮（JS禁用时显示） |

### 5.4 骨架屏

加载下一页时，在网格末尾插入 5 个骨架卡片：
- 封面区：灰色渐变占位
- 内容区：灰色线条占位（模拟标题、简介、标签）
- 动画：`pulse` 呼吸效果
- 加载完成后移除骨架，插入真实卡片

## 六、附带体验优化

### 6.1 「回到顶部」按钮

- 位置：右下角固定，`bottom: 24px; right: 24px`
- 触发：滚动超过 500px 时淡入，回到顶部后淡出
- 样式：圆形按钮，44×44px（满足触控最小尺寸），向上箭头图标
- 点击：平滑滚动到顶部（`scroll-behavior: smooth`）

### 6.2 卡片 Hover 效果

- 封面渐变：`filter: brightness(1.1)` 微亮
- 卡片整体：`transform: translateY(-2px)` 轻微上浮
- 阴影：`box-shadow` 加深
- 过渡：`transition: all 0.2s ease`

### 6.3 空结果优化

搜索/筛选无结果时：
- 显示「没有找到匹配的案件」
- 下方显示 3 个「热门推荐」案件（按难度排序或随机）
- 提供「清除筛选」按钮

## 九、后续恢复游戏入口的方法

当需要重新开放线上游戏入口时：
1. 移除 BaseLayout 中 `{isDev && ...)}` 条件
2. 移除 prototype 页面的线上遮罩
3. 无需修改其他代码，游戏功能本身未删除

## 十、风险与注意事项

1. **CSS Columns 与 Stretched Link**：瀑布流中 `break-inside: avoid` 可防止卡片被截断，但需测试长卡片表现
2. **无限滚动与 SEO**：纯客户端渲染的无限滚动可能影响搜索引擎收录，建议保留 `?page=N` URL 参数支持
3. **骨架屏闪烁**：加载过快时骨架屏可能闪烁，可加最小显示时间（300ms）
4. **360 安全软件**：git 操作可能受 DENY ACL 影响，需使用 C 盘临时对象目录变通方案
5. **线上构建验证**：修改后需 `npm run build` 验证构建成功，再推送部署
