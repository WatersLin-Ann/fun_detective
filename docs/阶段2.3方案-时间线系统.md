## 一、系统目标

### 核心价值
1. **增加推理维度**：除了证据关联，玩家还可以通过时间线发现矛盾
2. **增强沉浸感**：时间线让案件更真实，玩家需要梳理事件发生顺序
3. **审判支持**：时间线矛盾可以作为审判中的证据使用
4. **案件差异化**：不同案件有不同的时间线，增加 replay value

### 与现有系统的关系
- **证据关联系统**：证据↔证人的关联
- **时间线系统**：事件↔时间的关联，发现时间冲突
- **笔记系统**：时间线线索可以记录到笔记
- **审判系统**：时间线矛盾可以在审判中出示

## 二、数据结构设计

### 2.1 案件数据中的时间线

在案件数据文件中添加`timeline`字段：

```javascript
timeline: [
  {
    id: 'tl-001',
    time: '22:00',           // 时间点
    title: '列车发车',        // 事件标题
    description: '东方快车从贝尔格莱德站发车',  // 详细描述
    source: '场景描述',       // 线索来源（场景/证据/证人）
    sourceId: 'intro',       // 来源ID
    discovered: false,       // 是否已被玩家发现
    category: '行程'         // 分类：行程/证词/物证/推测
  },
  // ...
]
```

### 2.2 时间线矛盾

```javascript
timelineContradictions: [
  {
    id: 'tc-001',
    event1: 'tl-003',        // 事件1 ID
    event2: 'tl-005',        // 事件2 ID
    description: '赫伯德夫人说00:10有人在她包厢，但列车员说00:10在其他车厢',
    confidence: 15           // 发现后增加的信心值
  }
]
```

### 2.3 玩家状态

```javascript
state.discoveredTimeline = [];  // 已发现的时间线事件ID
state.timelineContradictionsFound = [];  // 已发现的时间线矛盾ID
```

## 三、功能设计

### 3.1 时间线索收集

#### 收集方式
1. **场景自动收集**：进入特定场景时，自动发现时间线索
2. **证据关联收集**：查看证据详情时，发现时间线索
3. **证人对话收集**：询问证人时，证词中包含时间信息
4. **关联推理收集**：建立证据关联后，解锁时间线索

#### 收集反馈
- 收集动画（与证据收集类似）
- Toast提示："发现时间线索：XXX"
- 自动添加到时间线页面

### 3.2 时间线页面

#### 页面布局
- 顶部：时间线标题 + 已发现数量
- 主体：垂直时间线，按时间排序
  - 每个事件显示：时间点、标题、描述、来源标签
  - 已发现的事件正常显示
  - 未发现的事件显示为"???"（不剧透）
- 底部：时间线矛盾检测按钮

#### 交互
- 点击事件查看详情
- 点击"检测矛盾"按钮，检查已发现事件中是否有矛盾
- 发现矛盾后显示矛盾提示，增加信心值

### 3.3 时间线矛盾检测

#### 检测逻辑
- 玩家点击"检测矛盾"按钮
- 系统检查已发现的事件中，是否有预设的矛盾组合
- 如果两个事件都已发现，且存在预设矛盾，则揭示矛盾
- 矛盾揭示后：
  - 显示矛盾详情
  - 增加信心值
  - 记录到state.timelineContradictionsFound
  - 可以在审判中作为证据使用

### 3.4 审判中的时间线

#### 使用方式
- 审判阶段，证人证词涉及时间时，可以出示时间线矛盾
- 时间线矛盾作为特殊证据类型
- 正确使用时间线矛盾可以额外增加信心值

## 六、风险和注意事项

### 风险1：时间线索收集触发点复杂
- **问题**：需要在多个地方添加收集触发点
- **解决**：先实现基础版本（场景进入自动收集），后续扩展

### 风险2：时间线矛盾逻辑复杂
- **问题**：矛盾检测需要预设组合，且要检查两个事件都已发现
- **解决**：使用预设矛盾配置，简化检测逻辑

### 风险3：UI空间有限
- **问题**：顶部栏已有多个按钮（证据/关联/笔记/音量）
- **解决**：时间线按钮可以放在笔记弹窗中作为Tab，或单独弹窗

### 注意事项
- 时间线事件不剧透：未发现的事件显示为"???"
- 时间线矛盾需要两个事件都发现才能检测
- 保持与证据关联系统的一致性
- 两个案件都要添加时间线数据
