## 任务 1.1：原型入口页 — 标题对比度修复 + 卡片语义化

### 问题
- P0-01：H1 使用 `text-white`，但 BaseLayout 主体为浅色背景，白字白底不可读
- P0-03：案件卡使用 `<div onclick="startCase()">`，无键盘支持、无语义、屏幕阅读器无法识别

### 修改内容

**`index.astro` 全面重写**：

| 改动项 | 旧实现 | 新实现 |
|--------|--------|--------|
| 页面背景 | 继承主站浅色（白字不可读） | 深色沉浸区域 `var(--game-bg)`，与游戏壳视觉一致 |
| 标题 | `text-white` H1 | `var(--game-text)` 深色底白字，对比度 ≥7:1 |
| 卡片元素 | `<div onclick="startCase(id)">` | `<a href="/fun_detective/game-design/prototype/play?case=id">` |
| CTA 文案 | 无（整张卡可点击但无明确提示） | 底部「开始案件 →」按钮，min-height 44px |
| 焦点样式 | 无 | `focus-visible:ring-2`，ring 颜色用 `var(--game-accent)` |
| 无障碍 | 无 aria-label | `aria-label="开始案件：XXX"` |
| 触控尺寸 | 未规范 | CTA 按钮 min-height 44px，卡片整体 ≥280px |
| 卡片样式 | Tailwind 硬编码色 | 全部使用 `var(--game-*)` CSS Token |

### 验收结果
- ✅ 入口页标题在深色背景上对比度 ≥7:1（远超 4.5:1 要求）
- ✅ 三案件卡均为 `<a>` 元素，href 指向正确的 play 页面
- ✅ Tab 键可聚焦到每张卡，有可见焦点环（amber 色 ring）
- ✅ 屏幕阅读器读出「开始案件：东方快车：推理审判」
- ✅ 卡片内有明确的「开始案件 →」CTA 文案
- ✅ 移动端 375px 下卡片单列布局，无横向滚动

## 任务 1.2：动态案件加载 — loading/error/retry 三态

### 问题
- P0-02：动态 script 加载无 loading/error UI，失败时用 `alert()` 打断沉浸
- P2-06：`alert()` 原生弹窗破坏游戏沉浸感
- 无加载超时保护，网络异常时页面永久空白

### 修改内容

**`play.astro` 新增两个全屏容器**：
- `#game-loading`：旋转加载动画 + 案件名 + 进度提示文案
- `#game-error`：错误图标 + 错误信息 + 「重试」/「返回案件列表」双按钮

**`gameState.js` 全面改造 `loadCaseData`**：

| 功能 | 实现 |
|------|------|
| 加载开始 | `showLoading(caseName)` 显示加载态，设置案件名 |
| 加载成功 | 至少显示 300ms 防闪烁，然后淡出 loading，执行 callback |
| 加载失败（script.onerror） | `showErrorPanel()` 显示错误面板，填入具体错误信息 |
| ID 不匹配 | 显示「案件数据异常，请刷新页面重试」 |
| 案件不存在 | 显示「未找到案件 XXX，请返回案件列表重新选择」 |
| 8 秒超时 | `setTimeout` 自动触发错误面板「加载超时，请检查网络连接后重试」 |
| 重试按钮 | 重新调用 `loadCaseData(caseId, callback)` |
| 返回按钮 | `window.location.href = '/fun_detective/game-design/prototype/'` |
| alert() 移除 | 全部 3 处 `alert()` 替换为错误面板 |

**新增导出函数**：`showLoading`、`hideLoading`、`showErrorPanel`

### 验收结果
- ✅ 代码中无 `alert(` 调用（全 src 目录扫描确认）
- ✅ 正常加载显示 loading 骨架屏 ≥300ms，内容就绪后淡出
- ✅ loading 态显示案件名和「加载推理素材、证物与证人档案」进度提示
- ✅ 错误面板有「重试」和「返回案件列表」两个按钮，均可点击
- ✅ 8 秒超时自动显示错误面板
- ✅ 断网或错误 case ID 时显示错误面板而非空白/alert

## 任务 1.3：教程锚点修复 + 按案件流程配置

### 问题
- P0-04：教程高亮目标 `#scene-tabs`、`#evidence-bar`、`#witness-list`、`#trial-btn` 均不存在
- 教程步骤硬编码为 investigation-trial 流程，逆转裁判（courtroom-only）不适用
- 教程完成标记存在游戏存档中，新游戏会重置导致重复触发
- 无视觉高亮效果，教程仅为文字弹窗

### 修改内容

**`guideUI.js` 教程系统重构**：

1. **按案件流程动态生成教程步骤**：
   - `investigation-trial`（东方快车、血字）：7 步 — 欢迎→案发现场→可调查热点→收集证据→推理笔记→更多工具→准备就绪
   - `courtroom-only`（逆转裁判）：6 步 — 欢迎来到法庭→法庭战场→证物已备好→询问与异议→更多工具→准备就绪

2. **独立 localStorage 教程标记**：
   - Key 格式：`fun-detective-tutorial-{caseId}`
   - 按案件隔离，完成后不再重复触发
   - 不依赖游戏存档（存档重置不影响教程状态）

3. **视觉高亮遮罩**：
   - `highlightElement(target)`：使用 `position:fixed` + `getBoundingClientRect()` 计算位置
   - 3px 案件主题色边框 + 发光阴影 + 脉冲动画
   - `scrollIntoView({block:'center'})` 确保元素在视口内
   - 不存在时 `console.warn` 并跳过，不阻塞流程

4. **存在性校验**：`getTourElement(target)` 查询 `[data-tour="..."]`，不存在时警告

### 验收结果
- ✅ 三案教程每个步骤都能正确高亮对应元素（data-tour 全部存在）
- ✅ 教程高亮元素在视口内（scrollIntoView 居中）
- ✅ 已完成教程的案件再次进入不重复触发（localStorage 标记）
- ✅ 教程可通过「跳过教程」按钮中断
- ✅ 逆转裁判教程为法庭专属步骤，不出现「收集证据」等调查阶段内容
- ✅ 高亮框使用 position:fixed，不依赖 offsetParent

## 任务 1.4：逆转裁判目标数据重写 + 校验规则

### 问题
- P1-04：逆转裁判 objectives 的 phase 全部为 `investigation`，但实际是 courtroom-only 纯法庭流程
- 目标类型只有 7 种旧类型，不支持按证人/证据/阶段的精细目标
- 校验脚本无 flowType-objectives 兼容性检查

### 修改内容

**`data-phoenix-wright.js` objectives 重写**：

| 旧目标（phase=investigation） | 新目标（phase=intro/trial） |
|-------------------------------|---------------------------|
| 了解案件概况 (collect_evidence) | 阅读案情摘要 (phase, intro) |
| 收集关键证据 (collect_evidence) | 质询山野星雄 (witness, wit-yama) |
| 询问证人 (interview_witness) | 发现证词矛盾 (contradiction) |
| 整理推理笔记 (open_notebook) | 出示关键证物 (evidence, ev-blackout) |
| 进入审判 (enter_trial) | 询问被告矢张 (witness, wit-yahari) |
| 质询证人 (question_all_witnesses) | 完成总结陈词 (phase, trial) |
| 出示证据 (present_evidence) | — |

**`guideUI.js` 新增 4 种目标类型支持**：
- `phase`：intro 目标在离开 intro 时完成；trial 目标在进入 closing 时完成
- `witness`：询问指定 witnessId 后完成
- `contradiction`：发现任意矛盾后完成
- `evidence`：收集或出示指定 evidenceId 后完成

**`validate-case-data.cjs` 新增校验规则**：
- `courtroom-only` 案件：所有 objectives 的 phase 不能是 `investigation`（违反报 error）
- `investigation-trial` 案件：至少有一个 objective 的 phase 是 `investigation`（违反报 warning）
- `trialRequirement` 缺少主门槛条件时 warning

**东方快车/血字的研究确认**：两案均有 investigation 阶段目标，符合 investigation-trial 流程。

### 验收结果
- ✅ `npm run validate:cases` 通过，0 错误（3 个 trialRequirement warning 为预期，将在阶段 2 解决）
- ✅ 逆转裁判游戏中目标列表显示法庭相关目标，不出现「收集证据」等调查目标
- ✅ 目标完成检测与实际游戏行为对应（询问证人→发现矛盾→出示证据→总结陈词）
- ✅ 校验脚本能正确检测 flowType 与 objectives 的不匹配
