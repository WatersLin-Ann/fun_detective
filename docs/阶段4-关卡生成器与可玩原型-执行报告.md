## 二、功能1：关卡生成器

### 2.1 页面信息
- **路径**：`/fun_detective/game-design/generator/`
- **文件**：`src/pages/game-design/generator/index.astro`
- **工具函数**：`src/lib/generator.ts`
- **数据API**：`/fun_detective/api/case-data.json`（56个案例，472.9KB）

### 2.2 功能特性

#### 案例选择
- 支持按名称搜索
- 显示案例类型、地区、诡计类型
- 智能推荐最适配的模板（高亮显示）
- 56个案例全部可选

#### 模板选择
- 5个游戏模板卡片展示
- 显示模板描述和核心循环
- 点击选择，高亮反馈

#### 生成结果
生成的关卡结构文档包含：
1. **基本信息**：案例名称、模板名称、核心诡计、适配诡计、难度评分
2. **阶段设计**（4阶段）：
   - 阶段名称
   - 玩家目标
   - 关键机制
   - 线索分配（按线索时机自动映射到对应阶段）
   - 设计要点（结合案例特点补充）
3. **机制配置表**：机制名称、实现方式、对应阶段
4. **改编建议**（如果案例有）：改编方向、核心玩法、关键机制、难度适配、改编说明

#### 导出功能
- **Markdown导出**：结构化文档，可直接复制使用
- **JSON导出**：结构化数据，可用于开发或导入其他工具
- 浏览器直接下载文件

### 2.3 核心算法

#### 线索分配映射
| 模板阶段 | 对应线索时机 |
|----------|-------------|
| 阶段1（案件发生/引入） | 开篇 |
| 阶段2（证据收集/探索） | 前期 |
| 阶段3（推理/辩论） | 中期 |
| 阶段4（真相揭露） | 后期、终局 |

#### 模板推荐算法
- 计算案例诡计类型与模板适配诡计的匹配数
- 按匹配数排序，推荐最适配的模板

## 三、功能2：可玩原型 - 东方快车：推理审判

### 3.1 页面信息
- **入口页**：`/fun_detective/game-design/prototype/`
- **游戏主页**：`/fun_detective/game-design/prototype/play`
- **游戏数据**：`src/data/prototype-orient-express.ts`
- **状态管理**：`src/lib/gameStore.ts`

### 3.2 游戏内容

#### 场景（5个）
1. **波洛的包厢**（开场）：文字叙述，引入案件
2. **列车走廊**：列车员、赫伯德夫人，可进入受害者包厢和餐车
3. **受害者包厢**：5件证据可收集（尸体、窗户、手帕、怀表、烟灰）
4. **餐车**（审判）：4个证人可询问
5. **结局**：最终选择和结局展示

#### 证据（5件）
| 证据 | 关键信息 |
|------|----------|
| 尸体 | 12处刀伤，深浅不一 |
| 敞开的窗户 | 窗台上无脚印，伪造逃走路线 |
| 手帕 | 绣着字母"H"，指向多位乘客 |
| 怀表 | 停在1:15，可能是案发时间 |
| 烟灰 | 两种烟灰，受害者只抽雪茄 |

#### 证人（6个）
| 证人 | 矛盾点 | 所需证据 |
|------|--------|----------|
| 列车员皮埃尔 | 怀表时间与证词矛盾 | 怀表 |
| 赫伯德夫人 | 手帕首字母H吻合 | 手帕 |
| 玛丽·德本汉 | 香烟灰与证词矛盾 | 烟灰 |
| 阿巴斯诺特上校 | 无矛盾点（辅助角色） | - |
| 德拉戈米罗夫公主 | 手帕俄文拼写像H | 手帕 |
| 安德烈伯爵夫人 | 无矛盾点（辅助角色） | - |

#### 矛盾点（4个）
- 正确指出矛盾：信心值 +20
- 错误出示证据：信心值 -10
- 揭露3个矛盾点后可进入结局

#### 结局（2个）
1. **真相大白**：选择揭露真相，将12名凶手交给警方
2. **法外容情**：选择隐瞒真相，理解12人的复仇动机

### 3.3 核心系统

#### 信心值系统
- 初始值：100
- 正确指出矛盾：+20（上限100）
- 错误出示证据：-10（下限0）
- 影响结局评价

#### 存档系统
- 自动保存到localStorage
- 入口页检测存档，显示"继续游戏"按钮
- 支持URL参数 `?continue=1` 直接继续
- 游戏内可重置

#### 游戏流程
```
开场文字叙述（12段）
    ↓
调查阶段（收集证据+询问证人）
    ↓ （≥3证据 + ≥3证人）
审判阶段（询问证人+指出矛盾）
    ↓ （≥3矛盾点）
结局阶段（选择+结局展示）
```

### 3.4 技术实现
- 纯前端实现，无后端依赖
- 游戏数据直接注入页面（静态构建）
- 状态管理：简单的全局状态对象 + localStorage
- UI：Tailwind CSS + 原生JS交互
- 组件化：4个可复用组件

## 八、已知限制与后续优化方向

### 当前限制
1. 关卡生成器的生成结果是结构化参考，仍需人工调整和细化
2. 原型只有1个案例（东方快车谋杀案），内容量有限
3. 原型只有推理审判模板的验证，其他4个模板尚未制作原型
4. 游戏画面较简单，主要是文字和简单图形
5. 无音效和背景音乐
6. 移动端体验未优化

### 阶段5预览（可选方向）
1. **更多原型**：基于密室逃脱、连环案件等模板制作可玩原型
2. **原型编辑器**：用户可以自定义案例和模板，生成自己的游戏
3. **生成器增强**：支持更细粒度的关卡调整和预览
4. **视觉增强**：为原型添加更好的视觉效果和动画
5. **音效系统**：添加背景音乐和音效
6. **移动端适配**：优化原型在移动端的体验
7. **社区分享**：用户可以分享自己生成的关卡结构和游戏原型
