# Fun Detective 部署方案与演进路线

> 制定日期：2026-09-13
> 状态：待执行（当前保持 GitHub Pages 静态部署）
> 核心原则：前期 0 成本自用，有真实外部用户需求后再逐步升级

---

## 一、需求背景

### 1.1 项目现状
- 技术栈：Astro 7.x + TypeScript + Tailwind CSS
- 部署方式：GitHub Pages 静态站点（`output: 'static'`）
- 数据规模：300+ 案件 JSON 文件（推理小说、影视、游戏、真实案件）
- 功能：案件浏览、多维度筛选、年代筛选、排序、分页、案件详情页

### 1.2 未来需求
| 需求 | 优先级 | 说明 |
|------|--------|------|
| 用户系统 | 中 | 收藏、笔记、阅读进度等延伸功能 |
| 定期更新 | 高 | 约每月一次案件数据更新 |
| 全文搜索 | 低 | 暂不需要 |
| 目标用户 | 国内 | 主要面向国内用户 |
| 成本控制 | 高 | 前期尽量 0 成本，自用为主 |

## 二、分阶段部署方案

### 阶段一：当前 — 0 成本自用（✅ 进行中）

#### 架构
```
GitHub Pages 静态站点 + 前端 localStorage
```

#### 技术选型
| 模块 | 方案 | 成本 |
|------|------|------|
| 前端页面 | Astro 静态构建，GitHub Pages 托管 | 0 |
| 案件数据 | JSON 文件，构建时打包 | 0 |
| 收藏功能 | `localStorage` 存储收藏 ID 列表 | 0 |
| 笔记功能 | `localStorage` 按案件 ID 存储笔记内容 | 0 |
| 阅读进度 | `localStorage` 记录阅读位置 | 0 |
| 数据更新 | 本地构建后 git push，每月一次 | 0 |

#### 功能实现要点
```javascript
// 收藏
localStorage.setItem('fd_favorites', JSON.stringify(['case-id-1', 'case-id-2']))

// 笔记（按案件ID索引）
localStorage.setItem('fd_note_case-id-1', '这是我的笔记内容...')

// 数据导出/导入（为后续迁移做准备）
// 导出：把所有 localStorage 数据打包成 JSON 下载
// 导入：从 JSON 文件恢复到 localStorage
```

#### 国内访问优化（可选）
- GitHub Pages 国内访问偏慢，自用可接受
- 如需加速：套 Cloudflare CDN（免费），香港/日本节点覆盖国内
- 配置方式：Cloudflare 代理 GitHub Pages 域名

#### 优点
- 完全零成本，不需要服务器和数据库
- 不需要备案，不需要运维
- 收藏/笔记存在浏览器本地，自用足够
- 数据可导出，后续迁移不丢失

#### 局限
- 收藏/笔记仅在当前浏览器，换设备不同步
- 无法做用户注册登录
- 无法做社区互动（评论、分享）

### 阶段二：有外部用户 — 轻量后端（待触发）

#### 触发条件（满足任一即可升级）
- 有 5 个以上外部用户在使用
- 需要多设备同步收藏/笔记
- 需要用户注册登录功能
- 想做社区功能（评论、分享笔记）

#### 架构
```
Cloudflare Pages（前端+边缘函数）+ Cloudflare D1（SQLite数据库）
```

#### 技术选型
| 模块 | 方案 | 免费额度 | 超出后成本 |
|------|------|---------|-----------|
| 前端页面 | Cloudflare Pages 静态托管 | 无限带宽 | - |
| SSR/API | Pages Functions（边缘函数） | 10 万次/天 | $0.30/百万次 |
| 数据库 | D1（SQLite） | 5GB 存储，1亿次读取/天 | $0.75/百万次写入 |
| 用户认证 | Cloudflare Access 或 邮箱验证码 | 免费 | - |
| 静态资源 | R2 对象存储（可选） | 10GB/月 | $0.015/GB |

#### 为什么选 Cloudflare
1. **免费额度最大**：无限带宽，D1 数据库免费，函数调用免费额度高
2. **国内访问较好**：全球 300+ 节点，香港/日本节点覆盖国内
3. **Astro 官方支持**：`@astrojs/cloudflare` 适配器，支持混合模式
4. **不需要备案**：海外平台，即开即用
5. **一体化**：前端、函数、数据库、CDN 都在一个平台

#### Astro 配置改造
```javascript
// astro.config.mjs
import { defineConfig } from 'astro/config';
import cloudflare from '@astrojs/cloudflare';

export default defineConfig({
  output: 'hybrid',  // 混合模式：大部分页面静态，动态页面SSR
  adapter: cloudflare(),
});
```

#### 数据库表设计（初步）
```sql
-- 用户表
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  email TEXT UNIQUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 收藏表
CREATE TABLE favorites (
  user_id TEXT,
  case_id TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, case_id)
);

-- 笔记表
CREATE TABLE notes (
  user_id TEXT,
  case_id TEXT,
  content TEXT,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, case_id)
);
```

#### 迁移工作清单
- [ ] 改造 Astro 为 `output: 'hybrid'`，加 Cloudflare 适配器
- [ ] 实现用户注册/登录 API（邮箱验证码）
- [ ] 实现收藏/笔记的 CRUD API
- [ ] 前端收藏/笔记从 localStorage 改为 API 调用
- [ ] 写数据迁移脚本：从 localStorage 导入到 D1
- [ ] 部署到 Cloudflare Pages
- [ ] 配置自定义域名（可选）
- **预计工作量：1-2 天**

### 阶段三：用户量增长 — 国内合规部署（待触发）

#### 触发条件
- 日活用户 > 100
- 对国内访问速度有极致要求
- 需要内容合规审核
- 需要更复杂的后端功能

#### 架构

## 五、关键决策记录

| 决策 | 理由 |
|------|------|
| 前期不急于上后端 | 每月一次更新频率，静态够用；自用为主，localStorage 足够 |
| 阶段二选 Cloudflare 而非 Vercel/Netlify | 免费额度最大，国内访问更好，一体化程度高 |
| 不选国内平台作为阶段二 | 需要备案，前期成本和流程过重；有真实用户后再考虑 |
| 数据用 JSON 而非数据库（阶段一） | 300+ 案件数据量小，JSON 简单直接，构建时打包性能好 |
