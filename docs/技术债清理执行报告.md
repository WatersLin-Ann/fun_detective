## 一、完成内容

### 1.1 拆分游戏数据为独立模块 ✅

**问题**：play.astro中内联了约6500字符的游戏数据JSON，与逻辑混在一起，修改困难。

**解决方案**：
- 新建 `src/game/data-orient-express.js`（~280行）
- 包含：scenes、evidence、witnesses、dialogs、contradictions、witnessColors
- 采用IIFE封装，挂载到 `window.GameData`
- play.astro中改为 `const gameScenes = GameData.scenes` 等引用

**收益**：
- play.astro从41200字符减少到34724字符（减少16%）
- 游戏数据与逻辑分离，便于维护和扩展
- 未来新增案件时只需新建数据文件

### 1.2 统一JS文件管理 ✅

**问题**：src/game和public/game有重复文件，修改时容易漏改一边。

**解决方案**：
- 新建 `scripts/sync-game-js.js` 构建脚本
- 自动将 `src/game/*.js` 同步到 `public/game/`
- 开发时只修改src/game，构建前运行同步脚本

**使用方式**：
```bash
node scripts/sync-game-js.js
```

**当前同步的文件**：
- data-orient-express.js
- ui.js
- playerData.js
- notebookUI.js

### 1.3 修复中文乱码问题 ✅

**问题**：之前用PowerShell的Set-Content修改文件导致中文乱码。

**解决方案**：
- 从git的b59b826版本恢复正确文件
- 用Python脚本（指定UTF-8编码）重新应用所有修改
- 后续所有文件修改一律用Python，不再用PowerShell的Set-Content

## 六、经验教训

1. **编码问题**：含中文的文件必须用Python（UTF-8）修改，不能用PowerShell的Set-Content
2. **数据与逻辑分离**：尽早拆分，避免单文件过大
3. **构建脚本**：重复文件用脚本同步，避免手动修改漏改
4. **渐进式重构**：不要一次性大重构，先拆数据，再拆逻辑，逐步进行
