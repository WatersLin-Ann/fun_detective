## 二、5批修复执行详情

### 第1批：引擎去硬编码

**目标**: 让通用引擎真正支持多案件，消除所有"东方快车"硬编码。

**修改文件**: `src/game/gameInteractions.js`, `src/game/gameRender.js`, `src/game/playerData.js`, `src/game/data-orient-express.js`, `src/game/data-study-in-scarlet.js`

**具体改动**:

1. **`__introContinue` 动态化** (`gameInteractions.js:45-82`)
   - 对话段数从硬编码12改为 `intro.length + investigationStart.length` 动态计算
   - 首场景从 `meta.firstScene` 读取，兼容数组/对象两种scenes结构
   - 支持 `flowType: 'courtroom-only'`：开场结束直接进入审判，证据全部预置

2. **`__exit` 动态化** (`gameInteractions.js:153-207`)
   - 审判场景从 `meta.trialScene` 读取（默认 dining-car）
   - 审判门槛从 `meta.trialRequirement` 读取（默认 {minEvidence:3, minWitnesses:2}）
   - 确认文案从 `meta.trialSceneName` 动态生成

3. **证人颜色动态化** (`gameInteractions.js:108`)
   - 优先读 `witness.color`，其次读案件 `witnessColors` 映射，最后默认灰色
   - 移除硬编码的6个东方快车证人颜色

4. **审判开场文案动态化** (`gameRender.js:234-262`)
   - 从案件 `trialOpening` 字符串数组读取
   - 无配置时用 `meta.name/victim/detective` 生成通用文案

5. **标签页标题动态化** (`gameRender.js:updateTopBar`)
   - `document.title` 动态设置为 `${caseName} | Fun Detective`
   - 页面内 `#case-title` 元素同步更新

6. **笔记导出标题动态化** (`playerData.js:250-254`)
   - 从 `window.GameData.meta.name` 读取，不再硬编码"东方快车谋杀案"

7. **三案件meta补全**
   - 东方快车: firstScene=corridor, trialScene=dining-car, trialSceneName=餐车
   - 血字: firstScene=crime-scene, trialScene=dining-car, trialSceneName=审判室
   - 两案均补 flowType=investigation-trial, trialRequirement

### 第2批：纯法庭流程 + 逆转裁判数据对齐

**目标**: 引擎支持 `courtroom-only` 纯法庭流程，逆转裁判数据结构与引擎契约统一。

**修改文件**: `src/game/data-phoenix-wright.js`, `src/game/gameState.js`

**具体改动**:

1. **逆转裁判 scenes 对象→数组** (`data-phoenix-wright.js:24-50`)
   - 原 `{intro, courtroom, witness}` 对象改为数组
   - 每个场景补 `interactables: []`, `exits: []`, `sceneType`, `background` 渐变

2. **逆转裁判 dialogs.intro 对象→字符串** (`data-phoenix-wright.js:148-160`)
   - 原 `{speaker, color, text}` 对象数组改为字符串数组（带角色前缀）
   - 这是 `[object Object]` 显示bug的根因

3. **补 investigationStart** (`data-phoenix-wright.js:161-166`)
   - 4段开庭过渡对话（法官宣布开庭、控方陈述、法官提示、成步堂准备）
   - 纯法庭案件开场总段数 = intro(4) + investigationStart(4) = 8

4. **逆转裁判 meta 补全** (`data-phoenix-wright.js:10-25`)
   - `title` 改 `name`（统一字段）
   - 补 `flowType: 'courtroom-only'`, `trialScene: 'courtroom'`, `trialSceneName: '法庭'`
   - `trialRequirement: {minEvidence:0, minWitnesses:0}`（纯法庭直接开庭）

5. **证据字段统一** (`data-phoenix-wright.js`)
   - `scene` → `foundIn`（6处）
   - `detail` → `keyInfo`（6处）

6. **证人补 followUpTestimony** (`data-phoenix-wright.js`)
   - 山野星雄: 追问时间和地点细节
   - 矢张政志: 追问吵架原因和离开时间
   - 法官: `followUpTestimony: null`（隐藏追问按钮）

7. **IIFE变量名统一** (`data-phoenix-wright.js:8, 308-309`)
   - `const GameData` → `const CaseData_phoenixWright`（避免全局const冲突）
   - 同时赋值 `window.CaseData_phoenixWright` 和 `window.GameData`

8. **补 trialOpening** (`data-phoenix-wright.js:290-294`)
   - 3段审判开场文案（法官宣布审理、控方主张、法官提示）

9. **getGameData 返回完整字段** (`gameState.js:182-207`)
   - 原只返回5个字段（gameScenes/gameEvidence/gameWitnesses/gameDialogs/gameContradictions）
   - 现返回完整案件数据 + game*别名，包含 objectives/endings/achievements/timeline/noteKeywords 等
   - 修复 guideUI/endingUI/timelineUI 拿不到数据的问题

### 第3批：交互健壮性

**目标**: 修复后台标签页弹层永久不可见、收集证据动画位置错误等问题。

**修改文件**: `src/game/ui.js`, `src/game/gameInteractions.js`, `src/game/gameRender.js`

**具体改动**:

1. **5处 rAF → setTimeout** (`ui.js`)
   - toast显示、对话框入场、证据卡片入场、modal入场、收集动画
   - `requestAnimationFrame` 在后台标签页不执行，导致元素永久 opacity:0
   - 改为 `setTimeout(..., 10)`，后台标签也能执行

2. **打字机跳过提示** (`ui.js:138-185`)
   - 长文本（>10字符）打字机期间显示"▸ 点击跳过"提示（右下角，animate-pulse）
   - 打字完成或点击跳过后移除提示
   - 原有点击跳过功能保留

3. **收集证据 event 解耦** (`gameInteractions.js:55, gameRender.js:196,199`)
   - `__interact(itemId)` 改为 `__interact(itemId, sourceRect)`
   - 场景元素 onclick 传入 `{left: event.clientX, top: event.clientY}`
   - 回调中使用传入的 sourceRect，无则用屏幕中心
   - 修复程序化调用时报错、真实点击时动画位置错误的问题

### 第5批：案件数据校验脚本

**目标**: 防止未来新增案件时数据结构不一致，build前自动校验。

**新增文件**: `scripts/validate-case-data.cjs`

**校验项**:
- meta: id/name必填，flowType/firstScene/trialScene建议
- scenes: 必须是数组，每个有id/name/interactables/exits
- evidence: id/name/description必填，检测废弃字段scene/detail
- witnesses: id/name/initialTestimony必填，followUpTestimony建议
- dialogs.intro: 必须是字符串数组（检测对象格式）
- contradictions: 建议为数组
- trialOpening: 建议为字符串数组
- IIFE变量名: 不能是GameData（避免全局冲突）

**集成**:
- `package.json` build命令改为 `node scripts/validate-case-data.cjs && astro build`
- 新增 `npm run validate:cases` 单独校验命令
- 新增 `npm run sync:game` 同步命令

**当前校验结果**: 3个案件，0错误，0警告 ✅

## 三、音频处理说明

**问题**: 用户尚未提供真实音乐文件，但游戏中播放了 Web Audio API 合成的占位音，且默认自动播放。

**解决方案**:
- `audio-config.js`: `settings.audioEnabled = false` 总开关
- `audioManager.js`: init/playTone/playBgm/playSfx 四个入口最前面判断总开关，直接return
- `gameRender.js`: 总开关关闭时隐藏顶部🔊音量按钮
- **架构保留**: 未来提供真实音频后只需置 `audioEnabled = true`
