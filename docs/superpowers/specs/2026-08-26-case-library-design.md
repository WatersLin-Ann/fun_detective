## 一、项目概述

### 1.1 目标
构建一个「全球案件案例库」，同时服务于两种用途：
- **阅读向**：作为小说/短文阅读，提供沉浸式案件故事
- **游戏设计向**：为推理/解谜游戏设计提供诡计参考、线索链结构、机制模板

### 1.2 核心原则
- **双轨并重**：每个案件同时交付「故事视图」和「设计视图」，缺一不可
- **按设计价值筛选**：不设真实/虚构比例，只要案件结构有学习和复用价值就收录，用标签区分来源
- **MVP 优先**：先用飞书 Base 跑通数据结构，验证字段设计后再考虑前端

### 1.3 产品形态
- **当前阶段**：飞书多维表格（Base）
- **主表**：案件库（一条记录 = 一个案件）
- **子表**：线索链（一条记录 = 一条线索，关联到案件）

## 四、标签体系

### 4.1 诡计类型（多选，必选至少1个）

| 标签 | 说明 |
|---|---|
| 密室 | 封闭空间内的不可能犯罪 |
| 不在场证明 | 利用时间、空间、证人制造不在场证明 |
| 叙述性诡计 | 利用叙述方式欺骗读者（如叙述者不可靠、时间线混淆） |
| 身份诡计 | 身份替换、一人多角、多人一角 |
| 心理操控 | 利用心理暗示、催眠、斯德哥尔摩等 |
| 时刻表 | 利用交通时刻表制造不可能 |
| 物理机关 | 机械装置、密室机关、延时装置 |
| 毒杀 | 下毒手法、毒理诡计 |
| 其他 | 不属于以上类型的特殊诡计 |

### 4.2 可复用机制（多选，可选）

| 标签 | 说明 |
|---|---|
| 封闭空间 | 暴风雪山庄、孤岛、密室等与外界隔绝的场景 |
| 限时破案 | 有明确时间压力（如"天亮前找出凶手"） |
| 多视角叙事 | 从多个角色视角交替叙述 |
| 连环案件 | 多个案件之间有联系 |
| 叙述者不可靠 | 讲故事的人本身在撒谎或有认知偏差 |
| 死亡信息 | 受害者留下的暗号/线索 |
| 其他 | 其他可复用的叙事/游戏机制 |

## 五、录入标准与流程

### 5.1 收录标准
一个案件值得收录，需满足以下至少一条：
- 诡计设计有独创性或教科书级的代表性
- 线索链结构清晰，有学习价值
- 叙事手法或信息差设计有参考意义
- 在推理文化中有重要地位（标杆案件）

### 5.2 录入流程
1. **新建案件记录**：填写基本信息（案件名称、来源类型、来源作品、地区、年代、案件状态、一句话简介）
2. **录入故事视图**：故事摘要 → 完整故事 → 人物关系 → 关键时间线 → 结局/真相
3. **录入设计视图**：核心诡计简述 → 诡计类型标签 → 可复用机制 → 信息差分析 → 红鲱鱼/误导 → 三项难度评分
4. **录入线索链**：在子表中逐条添加线索，关联到案件
5. **自检**：对照「录入自检清单」检查完整性
6. **标记状态**：录入状态改为「完整」

### 5.3 录入自检清单
- [ ] 基本信息完整（7个必填字段）
- [ ] 故事摘要不含剧透，完整故事有悬念感
- [ ] 人物关系覆盖所有主要角色
- [ ] 结局/真相清晰（悬案有假说标注）
- [ ] 核心诡计简述一句话能说清
- [ ] 诡计类型至少选1个
- [ ] 信息差分析有三段（读者/侦探/真相）
- [ ] 三项难度评分已填
- [ ] 线索链至少录入3条（关键线索+误导线索+背景信息各至少1条）
- [ ] 录入状态标记为「完整」

### 5.4 写作规范
- **完整故事**：800-2000字，小说化叙事，避免干巴巴的案情罗列；保留悬念，结局部分可加分割线标注"以下含结局"
- **信息差分析**：固定三段式格式——
  ```
  【读者/玩家已知】：……
  【侦探已知】：……
  【真相】：……
  【信息差设计分析】：……（说明这种信息差如何制造悬念/误导）
  ```
- **红鲱鱼/误导**：每条误导单独列出，说明"假线索内容 → 指向的错误结论 → 布置手法"

## 七、执行步骤

### 阶段一：创建飞书 Base（预计15分钟）
1. 新建多维表格，命名为「全球案件案例库」
2. 创建主表「案件库」，按字段设计逐一添加字段
3. 创建子表「线索链」，添加字段并设置关联到主表
4. 创建所有预设视图（5个表格视图 + 1个看板视图）
5. 设置筛选器预设
6. 设置「难度综合」公式字段

### 阶段二：录入首批案例（预计2-3小时）
1. 按录入流程逐个录入10个案例
2. 每个案例完成后跑自检清单
3. 录入过程中记录字段设计问题（如某个字段不够用、某个标签需要新增）

### 阶段三：复盘与调整（预计30分钟）
1. 检查10个案例的字段覆盖情况
2. 调整不合理的字段/标签
3. 更新设计文档

### 阶段四：后续迭代（按需）
- 案例量达到30+后，考虑是否需要新增维度表
- 案例量达到50+后，评估是否需要做前端展示页面
- 根据使用反馈，考虑添加「诡计组合器」等工具功能

## 八、后续迭代方向

### 8.1 内容扩展
- 持续收录新案件，目标：100个精品案例
- 按地区/年代/诡计类型做专题整理
- 增加「改编案例」：基于经典诡计改编的新案件骨架

### 8.2 功能扩展
- **诡计组合器**：从案例库提取元素，生成新案件骨架
- **难度曲线生成器**：输入目标难度，推荐线索投放节奏
- **案件解构器**：输入自定义案件，对照案例库给出新颖度评分和漏洞提示

### 8.3 产品形态升级
- 飞书 Base → 静态网页知识库（改善阅读体验）
- 静态网页 → 互动网页应用（增加工具功能）
- 考虑开放 API，供游戏引擎直接调用

## 九、风险与注意事项

1. **真实案件版权/伦理**：真实案件使用公开信息，避免涉及受害者隐私；未结案案件不做"真相断言"，只列假说
2. **虚构案件版权**：故事概述用自己的话改写，不大段原文摘抄；标注来源和创作者
3. **字段膨胀风险**：MVP 阶段严格控制字段数量，新字段需求先记录，复盘时统一评估
4. **录入质量**：每个案件必须通过自检清单才能标记为「完整」，避免半成品堆积
